# AI 서버 안건 분류 형식 (AI-02) v0.1 초안

> 안건 자동 분류(AI-02)에 필요한 세 가지 주고받음을 다룬다. 아직 백엔드와 확인하기 전의 AI 쪽 제안이다. 확정되면 이 문서를 최신 전체본 하나로 교체한다.
> 전사 줄을 받는 형식은 `input-contract.md`, 회의 중 요약을 보내는 형식은 `output-contract.md`에 있다.

- 근거: PRD v0.1 AI-02, 요구사항 REQ-061·062·065·079
- 예시 파일: `examples/api/` (아래 12장)

## 1. 목적과 범위

| 구분 | 내용 |
|---|---|
| 목적 | 회의 중 발언(전사 줄)을 사전에 등록한 안건에 연결하고, 지금 논의 중인 안건(현재 안건)을 알려 준다 |
| 다루는 것 | 안건 목록 받기, 분류 결과 보내기, 사람이 고친 분류 받기 |
| 이 문서 밖 | 사전 자료 첨부 내용 (이번 범위에서 제외, 추후 지원 예정), 현재 안건 요약(AI-03), 안건 상태 판정(AI-04), 주제 변경 감지(AI-06) |

## 2. 흐름

| 번호 | 내용 | 보내는 쪽 | 받는 쪽 | 방식 | 보내는 때 |
|---|---|---|---|---|---|
| 1 | 안건 목록 | 백엔드 | ai-service | `PUT /internal/meetings/{meetingId}/agendas` | 안건이 만들어지거나 바뀔 때 바로 |
| 2 | 분류 결과 | ai-service | 백엔드 | `PUT {백엔드 주소}/internal/meetings/{meetingId}/agenda-classification` | 줄 묶음을 처리한 뒤, 보낼 것이 있을 때 |
| 3 | 사람이 고친 분류 | 백엔드 | ai-service | `POST /internal/meetings/{meetingId}/agenda-corrections` | 안건 보드에서 고칠 때 바로 |

- 1번과 3번은 받으면 바로 응답하고, 분류는 뒤에서 처리한다. 모델 호출이 수십 초 걸릴 수 있어서 응답을 기다리게 하지 않는다 (`input-contract.md` 7장과 같은 방식).
- 2번은 요약 전송(`output-contract.md`)과 같은 방식으로 보낸다. 같은 백엔드 주소(`BACKEND_BASE_URL`)와 같은 재시도 규칙을 쓴다.

## 3. 공통 규칙

| 규칙 | 내용 |
|---|---|
| 필드 이름 | camelCase |
| 시간 단위 | 정수 밀리초. `atMs`는 회의 시작 기준 음성 시간 (`input-contract.md` 3장) |
| `meetingId` | 문자열 또는 정수 (연동 API 초안의 공통 규칙은 숫자). 주소의 값과 본문의 값이 문자열로 바꿔 비교해서 다르면 `400`. ai-service가 백엔드로 보낼 때는 받은 타입 그대로 쓴다 |
| `agendaId` | 안건 목록에서 받은 값을 타입 그대로 돌려준다. 문자열 또는 정수를 받는다 |
| `seq` | 전사 줄 번호. `input-contract.md`의 `lines[].seq`와 같다 |
| 해당 없음 | 어느 안건에도 맞지 않으면 `agendaId`가 `null`이다 |

## 4. 안건 목록 받기 (백엔드 → ai-service)

회의에 등록된 안건의 **최신 목록 전체**를 보낸다. 안건을 추가·수정·삭제·순서 변경할 때마다 일부가 아니라 전체를 다시 보내고, ai-service는 받은 목록으로 통째로 바꾼다. 같은 요청을 두 번 받아도 결과가 같다.

회의 시작 전에 보내도 되고, 회의 중 언제든 다시 보낼 수 있다.

### 4.1 본문

| 필드 | 타입 | 설명 |
|---|---|---|
| `meetingId` | 문자열 또는 정수 | 3장 규칙 |
| `version` | 정수 | 목록의 번호. 목록이 바뀔 때마다 커진다. 작거나 같은 번호는 무시한다 |
| `agendas` | 배열 | 안건 목록. 비어 있어도 받는다 |

### 4.2 agendas의 항목

| 필드 | 타입 | 설명 |
|---|---|---|
| `agendaId` | 문자열 또는 정수 | 안건 번호. 목록 안에서 겹치지 않는다 |
| `position` | 정수 | 안건 순서 (REQ-065). 1부터 |
| `title` | 문자열 | 안건 제목 (REQ-061). 비어 있으면 안 된다 |
| `decisionPoint` | 문자열 | 결정할 사항 (REQ-062) |
| `addedDuringMeeting` | 불리언 | 회의 중에 추가한 안건이면 `true`. 없으면 `false`로 본다 |

`status`, `pendingAgendaId` 등 다른 필드가 와도 쓰지 않고 무시한다.

### 4.3 응답

| 상황 | 응답 |
|---|---|
| 받음 | `200` + `{"accepted": true, "result": "accepted", "version": 3}` |
| 이미 받은 번호이거나 더 작은 번호 | `200` + `{"accepted": true, "result": "stale"}`. 반영하지 않는다 |
| 형식 오류, 주소와 본문의 `meetingId` 불일치, `agendaId` 중복, 제목이 빈 안건 | `400` + `{"error": "INVALID_INPUT", "detail": "이유"}` |
| 아직 받을 수 없음 | `503` + `{"error": "NOT_READY", "detail": "이유"}`. 백엔드는 나중에 다시 보낸다 |

## 5. 분류 결과 보내기 (ai-service → 백엔드)

줄 묶음을 처리한 뒤 **새로 분류했거나 결과가 바뀐 줄**과 현재 안건을 보낸다. 지금까지의 전체 분류표를 매번 보내지 않는다. 보낼 것이 없으면 보내지 않는다.

### 5.1 본문

| 필드 | 타입 | 설명 |
|---|---|---|
| `schemaVersion` | 문자열 | 지금은 `"0.1"` |
| `meetingId` | 문자열 또는 정수 | 3장 규칙 |
| `version` | 정수 | 보낼 때마다 커진다. 6장 규칙 |
| `atMs` | 정수 | 이 결과를 만든 시점의 음성 시각 |
| `final` | 불리언 | 회의 `end` 알림을 처리한 뒤의 마지막 결과이면 `true` |
| `currentAgendaId` | 안건 번호 또는 null | 지금 논의 중인 안건. 아직 연결된 줄이 없으면 `null` |
| `lines` | 배열 | 새로 분류했거나 바뀐 줄. 비어 있을 수 있다 |

### 5.2 lines의 항목

| 필드 | 타입 | 설명 |
|---|---|---|
| `seq` | 정수 | 전사 줄 번호 |
| `agendaId` | 안건 번호 또는 null | 연결된 안건. 해당 없음이면 `null` |

- 목록에 없는 줄은 "이번에 바뀌지 않았다" 또는 "분류 대상이 아니다"라는 뜻이다. 백엔드는 같은 `seq`를 받으면 새 값으로 덮어쓴다.
- 사람이 고쳐서 고정된 줄(7장)은 보내지 않는다. 백엔드가 이미 그 값을 갖고 있다.
- 분류 대상이 아닌 줄(맞장구, 간투사, 낮은 확신도)도 보내지 않는다 (8장 규칙 1).

### 5.3 마지막 결과

회의 `end` 알림을 처리한 뒤 `final`이 `true`인 결과를 한 번 보낸다. 바뀐 줄이 없어도 보낸다.

### 5.4 보내는 주기

- 줄 묶음(10초마다)을 처리할 때마다 결과가 바뀌었는지 본다. 모델 호출을 매 묶음마다 할지, 여러 묶음을 모아 할지는 구현 설정이고 평가 뒤에 정한다. 그래서 최대 지연은 이 문서에서 약속하지 않는다.
- `currentAgendaId`만 바뀌었거나 안건 삭제로 줄이 해당 없음으로 돌아간 경우에도 보낸다.

### 5.5 응답과 재시도

`output-contract.md` 5장과 같다.

| 백엔드 응답 | ai-service의 동작 |
|---|---|
| `2xx` | 성공 |
| `408`, `429`, `5xx`, 연결 오류 | 재시도 3회, 간격 1초·2초·4초 |
| 그 밖의 `4xx` | 다시 보내도 소용없으므로 포기하고 로그에 남긴다 |

요약과 다른 점이 하나 있다. 요약은 회의마다 최신 하나만 남기지만, 분류 결과는 바뀐 줄만 담으므로 옛것을 버리면 줄이 빠진다. 그래서 보내는 중에 더 새 결과가 생기면 두 결과를 `seq`별 최신 값으로 합쳐서 한 번에 보낸다. 재시도를 모두 써도 실패하면(`408`, `429`, `5xx`, 연결 오류) 보내지 못한 줄을 보관했다가 다음 결과에 합쳐 보낸다. 그 밖의 `4xx`는 같은 내용을 다시 보내도 같은 결과이므로 보관하지 않고 버린다.

## 6. version 규칙

- 같은 회의에서 보낼 때마다 커진다.
- 시각(밀리초) 이상의 값으로 시작해서, ai-service가 재시작해도 이전에 보낸 값보다 작아지지 않는다 (`output-contract.md` 4장과 같다).
- 백엔드는 이미 받은 값보다 작거나 같은 `version`을 버린다.
- 합쳐서 보낸 결과는 합친 것 중 가장 큰 `version`을 쓴다.

## 7. 사람이 고친 분류 받기 (백엔드 → ai-service)

사용자가 안건 보드에서 줄의 안건 연결을 고치면 백엔드가 바로 알린다.

### 7.1 본문

| 필드 | 타입 | 설명 |
|---|---|---|
| `meetingId` | 문자열 또는 정수 | 3장 규칙 |
| `corrections` | 배열 | 고친 줄. 한 번에 여러 줄을 보낼 수 있다 |

### 7.2 corrections의 항목

| 필드 | 타입 | 설명 |
|---|---|---|
| `seq` | 정수 | 고친 줄 번호 |
| `agendaId` | 안건 번호 또는 null | 사용자가 고른 안건. "해당 없음"으로 고쳤으면 `null` |
| `rev` | 정수 | 그 줄을 고칠 때마다 커지는 값. 시작값은 상관없고, 같은 `seq`는 `rev`가 큰 것만 반영한다 (`input-contract.md`의 `edits`와 같은 방식) |

### 7.3 ai-service의 처리

| 번호 | 규칙 |
|---|---|
| 1 | 고친 줄은 그 값으로 고정한다. 이후 자동 분류가 덮어쓰지 않고, 분류 결과(5장)에도 담지 않는다 |
| 2 | 고친 줄은 이후 줄을 분류할 때 직전 대화 흐름에 고친 값으로 들어간다 |
| 3 | 최근에 고친 줄 몇 건(기본 5건)을 이후 분류의 참고 예시로 모델에 보여 준다 |
| 4 | 아직 받지 못한 `seq`의 고침은 보관했다가 그 줄이 오면 적용한다 |
| 5 | 이미 삭제된 줄의 고침은 무시한다 |
| 6 | 안건 목록에 없는 `agendaId`도 받아서 보관한다. 안건 목록이 늦게 도착한 경우일 수 있어서다. 목록에 생기기 전까지는 참고 예시에서만 뺀다 |

### 7.4 응답

| 상황 | 응답 |
|---|---|
| 받음 | `200` + `{"accepted": true, "result": "accepted", "applied": 2}`. `applied`는 새로 반영한 줄 수 |
| 모두 이미 반영된 `rev` | `200` + `{"accepted": true, "result": "stale", "applied": 0}` |
| 형식 오류, 주소와 본문의 `meetingId` 불일치 | `400` + `{"error": "INVALID_INPUT", "detail": "이유"}` |
| 아직 받을 수 없음 | `503` + `{"error": "NOT_READY", "detail": "이유"}` |

## 8. ai-service의 분류 규칙

| 번호 | 규칙 |
|---|---|
| 1 | 분류 대상은 요약과 같다. `lowConfidence`가 `true`인 줄과 `kind`가 `backchannel`·`filler`인 줄은 뺀다. 사용자가 글을 고쳐서 낮은 확신도가 풀린 줄은 대상이 된다 |
| 2 | 줄 하나만 보지 않고 직전 대화 흐름(이미 분류된 앞쪽 줄과 그 결과)을 함께 보고 판단한다 |
| 3 | 어느 안건에도 맞지 않으면 해당 없음(`null`)으로 둔다. 해당 없음이 길게 이어지는 경우의 처리는 AI-06에서 다룬다 |
| 4 | 안건 목록이 아직 없으면 줄을 분류하지 않고 모아 둔다. 목록이 도착하면 모아 둔 줄을 분류한다 |
| 5 | 안건이 회의 중에 추가되거나 제목·결정할 사항이 바뀌어도 이미 분류된 줄은 다시 분류하지 않는다. 이후 줄부터 새 목록을 기준으로 한다 |
| 6 | 안건이 목록에서 사라지면 그 안건에 연결돼 있던 줄은 해당 없음으로 돌리고 다음 결과에 담는다. 사람이 고쳐서 연결한 줄도 같다 |
| 7 | 현재 안건은 마지막으로 연결된 안건을 유지한다. 해당 없음이 이어져도 이 단계에서는 바꾸지 않는다 |
| 8 | 이미 분류된 줄의 글이 나중에 수정돼도 다시 분류하지 않는다 |
| 9 | 삭제된 줄은 분류하지 않고, 이미 보낸 결과도 취소하지 않는다. 삭제는 백엔드가 알고 있다 |
| 10 | 로그와 상태 조회에 전사 내용과 안건 제목을 남기지 않는다. 회의 번호, 개수, 예외 이름만 남긴다 |

## 9. 복구

ai-service는 회의 상태를 메모리에만 둔다. 재시작하면 안건 목록, 고친 분류, 분류 결과가 모두 사라진다.

| 순서 | 내용 |
|---|---|
| 1 | 재시작 직후 모르는 회의의 줄 묶음이 오면 `409` + `{"expectedBatch": 1}`로 답한다 (`input-contract.md` 8장) |
| 2 | 백엔드는 그 회의의 줄 묶음을 1번부터 다시 보내기 전에 **최신 안건 목록(4장)과 그 회의의 고친 분류 전체(7장)를 먼저 다시 보낸다**. 사람이 고친 안건 요약 문장이 있으면 그것도 보낸다 (`agenda-summary-contract.md` 9장) |
| 3 | ai-service는 안건 목록을 받은 뒤 다시 받은 줄을 분류한다. 고친 줄은 고정되어 있으므로 사람의 수정은 유지된다 |

- 분류 결과의 `version`은 시각 기반이라 재시작 전보다 작아지지 않는다.
- 다시 분류하는 동안 이미 보낸 줄이 이전과 다른 안건으로 바뀔 수 있다. 백엔드는 같은 `seq`를 새 값으로 덮어쓴다.

## 10. 이번 범위에서 하지 않는 것

| 항목 | 이유 |
|---|---|
| 사전 자료(REQ-063) 분석 | 선택 항목이고 문서를 텍스트로 바꾸는 방식까지 정해야 해서 범위가 커진다. 추후 지원 예정이며 형식이 정해지면 4장의 `agendas` 항목에 필드를 추가한다 |
| 사용자가 현재 안건을 직접 바꾸는 기능을 ai-service에 알리기 | 연동 API 초안 3.1·3.2에 방향(백엔드 값이 우선이고 ai-service에 알린다)은 있으나, 지금 쓰는 전달 방식(회의 알림, 줄 묶음, 안건 목록, 고친 분류)에는 이 정보를 실을 곳이 없다. 전달 방식은 클라우드 팀(백엔드)에 확인을 요청했고, ai-service는 아직 구현하지 않았다 |
| 현재 안건 요약, 안건 상태 판정, 주제 변경 감지 | 각각 AI-03(`agenda-summary-contract.md`), AI-04, AI-06 |

## 11. 협의 상태

| 항목 | 상태 |
|---|---|
| 안건 목록을 전용 요청 하나로 받고 전체를 덮어쓴다 | AI 제안, 클라우드 팀(백엔드) 확인 필요 |
| 세 주소의 뒷부분 (`agendas`, `agenda-classification`, `agenda-corrections`) | AI 제안, 클라우드 팀(백엔드) 확인 필요 |
| `meetingId`·`agendaId`의 타입 (숫자 또는 문자열) | ai-service는 둘 다 받고 받은 타입 그대로 돌려준다. 백엔드가 실제로 보내는 타입은 확인 필요 |
| 안건 목록 `version`을 백엔드가 올린다 | AI 제안, 클라우드 팀(백엔드) 확인 필요 |
| 분류 결과를 ai-service가 `PUT`으로 밀어 주고, 새로 분류했거나 바뀐 줄만 담는다 | AI 제안, 클라우드 팀(백엔드) 확인 필요 |
| 백엔드가 줄별 분류 결과를 저장하고 안건 보드로 중계한다 | 클라우드 팀(백엔드) 확인 필요 |
| 고친 분류의 `rev` (줄마다 고칠 때마다 커지는 값, 시작값 무관, 큰 값만 반영) | AI 제안, 클라우드 팀(백엔드) 확인 필요 |
| 재시작 복구 때 백엔드가 안건 목록과 고친 분류를 먼저 다시 보낸다 | AI 제안, 클라우드 팀(백엔드) 확인 필요 |
| 안건 목록이 줄보다 늦게 도착할 때 줄을 모아 두었다가 분류한다 | AI 제안 |
| 분류 모델 호출 주기 | 30초로 정함 (평가 1회: 29분 회의에 59회, 오류 없음. `docs/eval/agenda-classification-eval-v1.md`). 베타에서 다시 본다 |
| 해당 없음이 이어질 때 현재 안건을 비울지 | 유지로 시작, AI-06 설계 때 다시 정한다 |
| 사용자가 현재 안건을 직접 바꾸는 기능의 전달 방식 | 미정. 클라우드 팀(백엔드)에 확인 요청함 (10장) |

### 11.1 안건 보드(연동 API 초안 3.2)와의 관계

연동 API 초안(2026-10-15)의 안건 보드 결과(3.2)는 합의된 형식이다. 안건 보드는 줄 단위 정보를 담지 않으므로, AI-02의 결과는 아래처럼 나눠서 보낸다. 별도 주소 세 개는 그대로 유지하고, 안건 보드에는 현재 안건과 안건별 요약이 들어간다 (AI-03, `agenda-summary-contract.md`).

| 내용 | 가는 곳 | 구현 시점 |
|---|---|---|
| 안건 목록 | 이 문서 4장 (`agendas`). 초안 3.1의 맥락 전달을 대신한다 | AI-02 |
| 줄별 분류 (`seq` → `agendaId`) | 이 문서 5장 (`agenda-classification`) | AI-02 |
| 현재 안건 | 5장의 `currentAgendaId`와 안건 보드의 `currentAgendaId`. 같은 값이며 화면은 안건 보드의 값을 쓴다 | AI-02 |
| 안건별 요약 | 안건 보드 `agendas[].summary` | AI-03 |
| 안건 상태, 의견·근거, 주제 변경 | 안건 보드 `agendas[].status`, `opinions`, `offTopic` | AI-04, AI-05, AI-06 |
