# AI 서버 먼저 알려드려요 - 용어 카드 형식 (AI-10 후보) v0.2 초안

> 회의 중 낯선 용어가 처음 나오면 뜻을 알려 주는 기능의 형식이다. 안건 보드(연동 API 초안 3.2)의 새 칸 `hints`(최근 카드)와 `terms`(찾은 용어 전체)를 채우고, 사용자가 카드를 닫거나 기능을 끄는 알림을 받는다.
> **v0.2는 화면 기획서(Figma `HiFi Flow Version01`의 Live_22 용어 감지·탭 알림, Live_23 내 도우미·용어 먼저 알려주기, Live_24 전사 속 용어 호버)와 요구사항 REQ-191을 반영한 AI 쪽 제안이다.** 서버에는 연결했고 **기본은 꺼져 있다**(`AGENDA_HINTS=1`일 때만 동작). 켜지 않으면 보드 모양은 예전과 같다. 기획팀·cn 팀·프론트 확인 전이라 모든 값이 바뀔 수 있다. 확정되면 이 문서를 최신 전체본 하나로 교체한다.
> 보드 전체 모양은 `agenda-summary-contract.md`에 있다.

- 근거: 노션 "기능 추가 제안: 먼저 알려드려요 · 회의 중 질문 챗봇 · 회의록 양식 가져오기" 1번, 요구사항 명세서 REQ-191(용어 감지. 비고: "AI 용어 감지 필요(ai-service 명세 협의). 지금 화면은 확인용 내장 용어 7개로만 찾음"), 화면 기획서 Live_22~24.
- 이 문서의 범위: **용어 카드만.** 지난 회의 카드(`PAST_MEETING`)는 포함하지 않는다.
- 모듈: `summary/agenda_hints.py` (`AgendaHints`, `Glossary`, `HintsCfg`). 서버 연결은 `server/service.py`. 시험은 `python3 agenda_hints.py --selftest`와 `python3 -m server.selftest`.
- 예시: `examples/api/agenda-board-hints-put.json`, `examples/api/hint-actions-dismiss-post.json`, `examples/api/hint-actions-disable-post.json`.

## v0.1에서 바뀐 것

| 바뀐 것 | 이유 |
|---|---|
| 보드에 `terms` 칸을 더했다 (이 회의에서 찾은 용어 **전체**) | 화면은 전사의 **모든 줄**에서 용어를 파랗게 칠하고 마우스를 올리면 뜻 카드를 띄운다(Live_24), 전사 탭에 용어 수를 센다(Live_22). `hints`는 최근 카드 3장뿐이라 부족하다 |
| `hints`·`terms`에 선택 필드 `name` (예: "리텐션 (Retention)")과 `terms`에 `aliases`를 더했다 | 뜻 카드의 제목이 "리텐션 (Retention)"처럼 원어를 함께 쓴다(Live_24). `aliases`는 같은 뜻의 다른 표기라 화면이 같이 칠한다 |
| 사용자 조작의 주소와 본문을 정했다 (`POST .../hint-actions`) | 서버에 연결했기 때문이다 |
| 환경변수와 보드 조립을 정했다 | 서버에 연결했기 때문이다 |

## 1. 목적과 범위

| 구분 | 내용 |
|---|---|
| 목적 | 회의 밖 사람이 모를 수 있는 용어를 회의를 멈추지 않고 알려 준다 |
| 다루는 것 | 보드 `hints`·`terms` 채우기, 카드 닫기·기능 끄기·켜기 알림 받기, 팀 용어집 형식 |
| 이 문서 밖 | 지난 회의 카드(회의록 검색 필요), 챗봇의 [더 묻기] 질문 만들기와 답(프론트가 챗봇 API로 묻는다), 화면 표현 |

## 2. 카드를 만드는 길

| 길 | 조건 | 모델 | `origin` | 뜻의 출처 |
|---|---|---|---|---|
| 용어집 | 용어집의 `term` 또는 `aliases`가 새 줄에 나옴 | 안 씀 | `GLOSSARY` | 용어집 문장 그대로 |
| AI 설명 | 용어집에 없는 낯선 말 | 씀 (`ai.task=agenda_hints`, 새 값) | `AI_EXPLAIN` | 모델이 쓴 한 줄, 코드가 확인 |

모델 길은 새 줄이 4개 모이거나(`min_new_lines`), 새 줄이 있는데 음성 시간으로 60초가 지나면(`refresh_sec`) 한 번 부른다. 한 번에 최대 30줄, 응답에서 최대 3개 용어를 받는다.

## 3. 보드의 hints 칸과 terms 칸

`AGENDA_HINTS=1`이면 보드 맨 위에 두 칸이 생긴다. **꺼져 있으면 두 칸 모두 보드에 없다**(키 자체가 없다). 켜져 있으면 카드가 없어도 빈 배열로 낸다. 프론트는 칸이 없을 때를 "기능 꺼짐"으로 읽는다.

```json
"hints": [
  {"id": "h-1", "kind": "TERM", "term": "리텐션", "name": "리텐션 (Retention)", "text": "한 번 쓴 사용자가 다시 돌아와 계속 쓰는 비율이에요.", "origin": "GLOSSARY", "evidenceSeqs": [214]},
  {"id": "h-2", "kind": "TERM", "term": "코호트", "text": "비슷한 조건의 사용자 묶음이에요.", "origin": "AI_EXPLAIN", "evidenceSeqs": [231]}
],
"terms": [
  {"id": "h-1", "term": "리텐션", "name": "리텐션 (Retention)", "aliases": ["retention"], "text": "한 번 쓴 사용자가 다시 돌아와 계속 쓰는 비율이에요.", "origin": "GLOSSARY", "firstSeq": 214},
  {"id": "h-2", "term": "코호트", "aliases": [], "text": "비슷한 조건의 사용자 묶음이에요.", "origin": "AI_EXPLAIN", "firstSeq": 231}
]
```

**`hints`: 내 도우미의 "먼저 알려 드려요 · 용어" 카드(Live_23)**

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | string | 회의 안에서 유일. `h-1`, `h-2`... 순서대로 |
| `kind` | string | 지금은 `TERM`만 |
| `term` | string | 전사에 나온 표기 (모델 길은 앞뒤 공백만 뺀 것) |
| `name` | string, 선택 | 화면에 보일 이름. **용어집 길에만 있다** (용어집의 `name`). 없으면 화면은 `term`을 쓴다 |
| `text` | string | 한 줄 뜻. 60자 이하 |
| `origin` | string | `GLOSSARY` / `AI_EXPLAIN`. 화면은 `AI_EXPLAIN`에 "AI 설명" 표시를 붙이는 것을 제안한다 |
| `evidenceSeqs` | int[] | 그 용어가 나온 전사 줄 번호 (비어 있지 않음). "14:29 발언에서"는 이 줄의 시각이다 |

- 닫지 않은 카드 중 **가장 최근 3장**만 담는다. 더 만들어지면 가장 오래된 카드는 목록에서 빠진다.

**`terms`: 전사 속 용어 표시와 뜻 카드(Live_24), 전사 탭의 용어 수(Live_22)**

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | string | `hints`의 카드와 같은 값 |
| `term` | string | 전사에서 칠할 표기 |
| `name` | string, 선택 | 뜻 카드 제목 (`hints`와 같음) |
| `aliases` | string[] | 같은 뜻의 다른 표기. 화면이 `term`과 함께 칠한다. 용어집 길만 값이 있고 모델 길은 빈 배열 |
| `text` | string | 한 줄 뜻 |
| `origin` | string | `GLOSSARY` / `AI_EXPLAIN` |
| `firstSeq` | int | 그 용어가 처음 나온 전사 줄 번호 |

- `terms`는 이 회의에서 **지금까지 찾은 용어 전부**다. **사용자가 닫은 카드도 남긴다**(닫기는 내 도우미의 알림만 거두는 것이고, 전사에서 이미 칠한 용어와 뜻 카드는 유지한다는 제안). 오래된 것부터 최대 200개까지 남긴다.
- 용어 수는 `terms`의 길이로 센다.
- 같은 용어(별칭 포함)는 회의 한 번에 한 번만 `terms`에 들어간다. 닫은 카드와 목록에서 빠진 카드도 다시 만들지 않는다.
- **새 용어를 찾는 것은 새 줄이 들어올 때뿐이다.** 용어를 찾기 전에 나온 줄은 그 용어가 `terms`에 들어온 뒤에야 칠할 수 있다(프론트가 `terms`로 전사 전체를 다시 칠한다고 이해한다).
- 보드는 지금처럼 값이 바뀔 때만, 초당 1회 이하로 통째로 PUT한다. `hints`나 `terms`가 바뀌면 보드가 바뀐 것으로 본다.
- 보드 저장과 전달: 지금 백엔드(meeting-service)는 보드 본문을 **그대로 저장하고 방에 전달**한다(`receiveBoard`). 그래서 두 칸을 더해도 저장·전달은 백엔드 수정 없이 된다고 읽었다(**확인 필요**).

## 4. 코드가 확인하는 것 (모델 길)

| 확인 | 어기면 |
|---|---|
| 용어가 근거 줄 안에 실제로 있다 (영문은 대소문자 무시, 앞뒤가 영문·숫자이면 다른 말) | 버림 (오류로 셈) |
| 그 글자가 STT 불확실 표시 안에 있지 않다 | 버림 |
| 용어 2~20자 한 줄, 뜻 한 줄 60자 이하, 뜻에 「」 인용 없음 | 버림 |
| 근거 번호가 입력 범위 안이다 | 버림 |
| `confident`가 true다 | 조용히 건너뜀 (오류로 안 셈) |
| 이미 안내한 용어, 용어집에 있는 용어, 안건 제목에 든 말 | 조용히 건너뜀 |

- 낮은 확신도 줄과 맞장구·간투사 줄은 입력에서 뺀다. 한 번 본 줄은 나중에 고쳐져도 다시 보지 않는다.
- 응답이 JSON이 아니거나 모양이 틀리면 오류를 알려 1번 더 부르고, 또 틀리면 실패로 센다.
- 연속 3번 실패하거나 회의당 호출 상한(60)에 닿으면 **모델 호출만** 멈춘다. 용어집 길은 계속된다.
- 모델 실패는 보드 전송을 막지 않는다 (다른 단계와 같음).

## 5. 팀 용어집 (JSON 파일)

```json
{"terms": [{"term": "리텐션", "name": "리텐션 (Retention)", "aliases": ["retention"], "explain": "한 번 쓴 사용자가 다시 돌아와 계속 쓰는 비율이에요."}]}
```

- `term` 2~20자, `explain` 한 줄 60자 이하, `aliases`는 선택, **`name`은 선택이고 한 줄 2~40자(v0.2)**. 이름(term, aliases)은 서로 겹치면 안 된다. 어긋나면 읽을 때 오류(`ValueError`)이고, 서버는 시작할 때 설정 오류로 멈춘다.
- `AGENDA_HINTS_GLOSSARY_PATH`가 가리키는 파일이 없으면 시작할 때 설정 오류다(경로 오타를 빈 용어집으로 넘기지 않는다). 경로를 비우면 빈 용어집이고 모델 길만 동작한다.
- 이 파일에 무엇을 넣을지는 팀이 정한다. **내용은 아직 없다.** 화면 확인용 내장 용어 7개(리텐션, 온보딩, KPI, MVP, 이탈률, 우선순위, QA)가 프론트 `termGlossary.ts`에 있으니 첫 용어집의 후보다.

## 6. 사용자의 조작

`POST /internal/meetings/{meetingId}/hint-actions` (`AGENDA_HINTS=1`일 때만 받는다)

```json
{"meetingId": "m_1234", "action": "dismiss", "rev": 3, "hintId": "h-2"}
{"meetingId": "m_1234", "action": "disable", "rev": 4}
```

| `action` | 필드 | AI 서버 동작 |
|---|---|---|
| `dismiss` | `hintId` 필수 | 그 카드를 `hints`에서 빼고 같은 용어를 다시 만들지 않음. `terms`에는 남음 |
| `disable` | - | "먼저 알려드려요"를 끔: `hints`·`terms`가 빈 배열이고 카드도 모델 호출도 없음 |
| `enable` | - | 다시 켬: 그 뒤 줄부터 봄. 이미 만든 카드는 다시 보인다 (닫은 카드는 제외) |

- `rev`는 조작마다 늘어나는 정수다. 앞서 받은 `rev`보다 크지 않으면 오래된 요청이라 `stale`로 돌려주고 무시한다 (끄기 `rev: 4` 뒤에 늦게 온 닫기 `rev: 3`이 상태를 바꾸지 않게).
- 응답: `{"accepted": true, "result": "accepted" | "stale" | "not_found", "applied": true|false}`. 모르는 `hintId`는 `not_found`. 회의가 끝났으면 `{"accepted": false, "result": "ignored", "reason": "ended"}`, 기능이 꺼져 있으면 `{"accepted": false, "result": "ignored", "reason": "off"}`. 형식이 틀리면 400.
- 받아들이면 다음 주기에 바뀐 `hints`·`terms`로 보드를 다시 보낸다.
- **조작을 어느 화면에서 어떻게 하는지는 화면 기획서에서 못 찾았다**(카드 닫기 버튼, 끄기 설정 위치). 기획 확인이 필요하다.

## 7. 설정

환경변수 (모두 기본은 꺼짐 또는 제안값)

| 이름 | 기본값 | 설명 |
|---|---|---|
| `AGENDA_HINTS` | 0 | `1`이면 켠다. `0`·`1`이 아니면 시작할 때 설정 오류 |
| `AGENDA_HINTS_GLOSSARY_PATH` | 없음 | 팀 용어집 JSON 경로 (5장) |
| `AGENDA_HINTS_REFRESH_SEC` | 60 | 새 줄이 있는데 이 시간(음성 시간)이 지나면 용어 후보를 찾음 |
| `MAX_AGENDA_HINTS_CALLS_PER_MEETING` | 60 | 회의당 모델 호출 상한 |

모듈 설정 (환경변수로 바꾸지 않는 값, 제안)

| 이름 | 기본값 | 설명 |
|---|---|---|
| `min_new_lines` | 4 | 새 줄이 이만큼 모이면 용어 후보를 찾음 |
| `max_lines` | 30 | 모델 한 번에 주는 줄 수 |
| `max_cards` | 3 | `hints`에 담는 카드 수 |
| `max_per_call` | 3 | 한 번의 응답에서 받는 용어 수 |
| `max_terms` | 200 | `terms`에 담는 용어 수 상한 |

모델은 요약과 같은 `LLM_PROVIDER`, `LLM_MODEL`을 쓴다.

## 8. 토큰 지표와 로그

- `ai.task` 새 값 `agenda_hints`. 켜기 전에 cn 팀 집계가 알아보는지 확인해야 한다.
- 로그와 상태 조회(`GET /internal/meetings/{id}/status`의 `agendaHints`. 꺼져 있으면 `null`)에는 전사 내용, 안건 제목, 용어, 뜻을 남기지 않는다. 개수와 예외 이름만 남긴다. 시험으로 확인했다.

## 9. 복구

AI 서버가 재시작하면 만든 카드와 닫은 기록과 꺼 둔 상태가 사라진다. 그대로 두면 이미 닫은 카드가 **다시 뜰 수 있고** 꺼 둔 기능이 **다시 켜진다.** 해결 방안은 정하지 않았다 (후보: 백엔드가 닫은 카드 용어와 끈 상태를 복구 때 먼저 보내기). 줄 묶음을 처음부터 다시 받으면 용어집 길의 카드와 `terms`는 다시 만들어진다. 모델 길은 닫은 기록이 없으면 같은 용어가 새 `id`로 다시 만들어질 수 있다.

## 10. 이번 범위에서 하지 않는 것

- 지난 회의 카드 (회의록 검색, 보드의 `source` 칸, 폴더 범위 결정 필요)
- 챗봇 [더 묻기] 연결 (프론트가 `term`으로 "리텐션이 뭐야?"를 챗봇에 묻는다. 지금 프론트 `termGlossary.ts`의 `askAbout`이 그렇게 한다)
- 모델을 부르는 평가: 용어 후보를 얼마나 잘 고르는지, 뜻이 맞는지는 **아직 재 보지 않았다.** 프롬프트는 시험된 적이 없다. **그래서 기본은 꺼짐이다.**
- 용어집 내용 만들기
- 전사에서 용어의 글자 위치(offset)를 주는 것 (프론트가 `term`과 `aliases`로 글자를 찾아 칠한다고 가정)

## 11. 협의 상태

| 상대 | 확인할 것 | 상태 |
