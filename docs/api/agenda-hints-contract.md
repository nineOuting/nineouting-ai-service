# AI 서버 먼저 알려드려요 - 용어 카드 형식 (AI-10 후보) v0.1 초안

> 회의 중 낯선 용어가 처음 나오면 뜻을 알려 주는 카드의 형식이다. 안건 보드(연동 API 초안 3.2)의 새 칸 `hints`를 채우고, 사용자가 카드를 닫거나 기능을 끄는 알림을 받는 제안이다.
> **구현은 모듈(`summary/agenda_hints.py`)과 자체 시험까지만 되어 있고 서버에는 연결하지 않았다.** 기획팀 범위 확인과 cn 팀 확인 전의 AI 쪽 제안이라 모든 값이 바뀔 수 있다. 확정되면 이 문서를 최신 전체본 하나로 교체한다.
> 보드 전체 모양은 `agenda-summary-contract.md`에 있다.

- 근거: 노션 "기능 추가 제안: 먼저 알려드려요 · 회의 중 질문 챗봇 · 회의록 양식 가져오기" 1번. 요구사항 명세서에는 용어 설명이 없다 (가까운 것은 REQ-067 사전 자료, Could, 미착수).
- 이 문서의 범위: **용어 카드만.** 지난 회의 카드(`PAST_MEETING`)는 포함하지 않는다.
- 모듈: `summary/agenda_hints.py` (`AgendaHints`, `Glossary`, `HintsCfg`). 시험은 `python3 agenda_hints.py --selftest`.

## 1. 목적과 범위

| 구분 | 내용 |
|---|---|
| 목적 | 회의 밖 사람이 모를 수 있는 용어를 회의를 멈추지 않고 알려 준다 |
| 다루는 것 | 보드 `hints` 채우기, 카드 닫기·기능 끄기 알림 받기, 팀 용어집 형식 |
| 이 문서 밖 | 지난 회의 카드(회의록 검색 필요), 챗봇의 [더 물어보기], 화면 표현 |

## 2. 카드를 만드는 길

| 길 | 조건 | 모델 | `origin` | 뜻의 출처 |
|---|---|---|---|---|
| 용어집 | 용어집의 `term` 또는 `aliases`가 새 줄에 나옴 | 안 씀 | `GLOSSARY` | 용어집 문장 그대로 |
| AI 설명 | 용어집에 없는 낯선 말 | 씀 (`ai.task=agenda_hints`, 새 값) | `AI_EXPLAIN` | 모델이 쓴 한 줄, 코드가 확인 |

모델 길은 새 줄이 4개 모이거나(`min_new_lines`), 새 줄이 있는데 음성 시간으로 60초가 지나면(`refresh_sec`) 한 번 부른다. 한 번에 최대 30줄, 응답에서 최대 3개 용어를 받는다.

## 3. 보드의 hints 칸

`hints`는 보드의 맨 위 칸이다. 카드가 없거나 기능이 꺼져 있으면 빈 배열이다.

```json
"hints": [
  {"id": "h-1", "kind": "TERM", "term": "리텐션", "text": "앱을 다시 찾는 사용자 비율이에요.", "origin": "GLOSSARY", "evidenceSeqs": [214]},
  {"id": "h-2", "kind": "TERM", "term": "코호트", "text": "비슷한 조건의 사용자 묶음이에요.", "origin": "AI_EXPLAIN", "evidenceSeqs": [231]}
]
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | string | 회의 안에서 유일. `h-1`, `h-2`... 순서대로 |
| `kind` | string | 지금은 `TERM`만 |
| `term` | string | 전사에 나온 표기 (모델 길은 앞뒤 공백만 뺀 것) |
| `text` | string | 한 줄 뜻. 60자 이하 |
| `origin` | string | `GLOSSARY` / `AI_EXPLAIN`. 화면은 `AI_EXPLAIN`에 "AI 설명" 표시를 붙이는 것을 제안한다 |
| `evidenceSeqs` | int[] | 그 용어가 나온 전사 줄 번호 (비어 있지 않음) |

- 보드에는 닫지 않은 카드 중 **가장 최근 3장**만 담는다. 더 만들어지면 가장 오래된 카드는 목록에서 빠지고 화면이 접는다고 이해한다.
- 같은 용어(별칭 포함)는 회의 한 번에 한 번만 카드가 된다. 닫은 카드와 목록에서 빠진 카드도 다시 만들지 않는다.
- 보드는 지금처럼 값이 바뀔 때만, 초당 1회 이하로 통째로 PUT한다. `hints`가 바뀌면 보드가 바뀐 것으로 본다.

## 4. 코드가 확인하는 것 (모델 길)

| 확인 | 어기면 |
|---|---|
| 용어가 근거 줄 안에 실제로 있다 (영문은 대소문자 무시, 앞뒤가 영문·숫자이면 다른 말) | 버림 (오류로 셈) |
| 그 글자가 STT 불확실 표시 안에 있지 않다 | 버림 |
| 용어 2~20자 한 줄, 뜻 한 줄 60자 이하, 뜻에 「」 인용 없음 | 버림 |
| 근거 번호가 입력 범위 안이다 | 버림 |
| `confident`가 true다 | 조용히 건너뜀 (오류로 안 셈) |
| 이미 안내한 용어, 용어집에 있는 용어, 안건 제목에 든 말 | 조용히 건너뜀 |

- 낮은 확신도 줄과 맞장구·간투사 줄은 입력에서 뺀다. 한 번 본 줄은 나중에 고쳐져도 다시 보지 않는다.
- 응답이 JSON이 아니거나 모양이 틀리면 오류를 알려 1번 더 부르고, 또 틀리면 실패로 센다.
- 연속 3번 실패하거나 회의당 호출 상한(60)에 닿으면 **모델 호출만** 멈춘다. 용어집 길은 계속된다.

## 5. 팀 용어집 (JSON 파일)

```json
{"terms": [{"term": "리텐션", "aliases": ["retention"], "explain": "앱을 다시 찾는 사용자 비율이에요."}]}
```

- `term` 2~20자, `explain` 한 줄 60자 이하, `aliases`는 선택. 이름(term, aliases)은 서로 겹치면 안 된다. 어긋나면 읽을 때 오류(`ValueError`)다.
- 파일이 없거나 경로가 비어 있으면 빈 용어집이다 (모델 길만 동작).
- 이 파일에 무엇을 넣을지는 팀이 정한다. **내용은 아직 없다.**

## 6. 사용자의 조작 (제안)

| 조작 | 알림 | AI 서버 동작 |
|---|---|---|
| 카드 닫기 | 카드 `id`를 보냄 (주소·본문은 아직 정하지 않음) | 그 카드를 목록에서 빼고 같은 용어를 다시 만들지 않음. 모르는 `id`는 `not_found` |
| "먼저 알려드려요" 끄기·켜기 | on/off (주소·본문은 아직 정하지 않음) | 끄면 `hints`는 빈 배열이고 카드도 모델 호출도 없음. 켜면 그 뒤 줄부터 봄 |

## 7. 설정

| 이름 | 기본값 | 설명 |
|---|---|---|
| `min_new_lines` | 4 | 새 줄이 이만큼 모이면 용어 후보를 찾음 |
| `refresh_sec` | 60 | 새 줄이 있는데 이 시간(음성 시간)이 지나면 찾음 |
| `max_lines` | 30 | 모델 한 번에 주는 줄 수 |
| `max_calls` | 60 | 회의당 호출 상한 |
| `max_cards` | 3 | 동시에 보이는 카드 수 |
| `max_per_call` | 3 | 한 번의 응답에서 받는 용어 수 |

환경변수는 만들지 않았다 (연결할 때 정한다). 모든 값은 제안이다.

## 8. 토큰 지표와 로그

- `ai.task` 새 값 `agenda_hints`. 연결 전에 cn 팀 집계가 알아보는지 확인해야 한다.
- 로그와 상태 조회(`info()`)에는 전사 내용, 안건 제목, 용어, 뜻을 남기지 않는다. 개수와 예외 이름만 남긴다. 시험으로 확인했다.

## 9. 복구

AI 서버가 재시작되면 만든 카드와 닫은 기록이 사라진다. 그대로 두면 이미 닫은 카드가 **다시 뜰 수 있다.** 해결 방안은 정하지 않았다 (후보: 백엔드가 닫은 용어 목록을 복구 때 먼저 보내기). 줄 묶음을 처음부터 다시 받으면 용어집 길의 카드는 같은 순서로 다시 만들어진다.

## 10. 이번 범위에서 하지 않는 것

- 지난 회의 카드 (회의록 검색, 보드의 `source` 칸, 폴더 범위 결정 필요)
- 챗봇 [더 물어보기] 연결
- 서버 연결, 환경변수, 백엔드 주소, 보드 조립 변경
- 모델을 부르는 평가: 용어 후보를 얼마나 잘 고르는지, 뜻이 맞는지는 **아직 재 보지 않았다.** 프롬프트는 시험된 적이 없다.
- 용어집 내용 만들기
