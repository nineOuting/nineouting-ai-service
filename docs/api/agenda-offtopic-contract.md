# AI 서버 주제 변경 감지·새 안건 제안 형식 (AI-06) v0.1 초안

> 등록된 안건과 관계없는 이야기가 오래 이어질 때 새 안건 등록을 제안하는 방식을 다룬다. 안건 보드(연동 API 초안 3.2)의 `offTopic` 칸을 채우고, 제안을 무시했다는 알림을 받는다. 아직 cn 팀과 확인하기 전의 AI 쪽 제안이다. 확정되면 이 문서를 최신 전체본 하나로 교체한다.
> 안건 목록과 줄별 분류는 `agenda-contract.md`, 보드 전체 모양은 `agenda-summary-contract.md`에 있다.

- 근거: PRD v0.1 AI-06, 요구사항 REQ-091·092, 연동 API 초안 3.2 (안건 보드 결과의 `offTopic`)
- 설계 결정: `ai06-design-decisions-v1.md` (프로젝트 문서)
- 예시 파일: `examples/api/agenda-board-offtopic-put.json`, `off-topic-action-post.json`, `off-topic-action-replay-post.json`
- 평가: 평가 도구는 `summary/eval_agenda_offtopic.py`, 결과는 평가 뒤 `docs/eval/`에 둔다

## 1. 목적과 범위

| 구분 | 내용 |
|---|---|
| 목적 | 회의가 등록된 안건에서 벗어나 다른 이야기로 길게 이어지면 새 안건 등록을 제안하고, 제안을 무시한 뒤에도 이어지면 "지금 다른 이야기를 하고 있다"고 알린다 |
| 다루는 것 | 안건 보드 `offTopic` 채우기, 제안을 무시했다는 알림 받기, 새 안건 제목 제안 |
| 이 문서 밖 | 새 안건을 실제로 만드는 일(백엔드와 화면이 한다. AI 서버는 안건 목록 전체를 다시 받아 알게 된다), 화면 표현 |

## 2. 흐름

1. AI 서버는 줄별 분류(AI-02)에서 "해당 없음"이 끊김 없이 이어진 가장 최근 구간을 본다.
2. 구간이 **60초**에 닿으면 보드의 `offTopic`을 `SUGGEST`로 채우고, 이때 모델을 한 번 불러 새 안건 제목을 만든다.
3. 사용자가 제안을 닫으면 백엔드가 5장의 요청으로 알린다. AI 서버는 `offTopic`을 `null`로 되돌린 보드를 보낸다.
4. 무시한 시각부터 해당 없음이 **180초** 더 이어지면 `offTopic`을 `LONG`으로 채운다.
5. 사용자가 새 안건을 등록하면 백엔드가 안건 목록 전체를 다시 보낸다(`agenda-contract.md` 4장). 처음 보는 안건이 들어오면 AI 서버는 떠 있던 제안을 거둔다.
6. 안건 줄이 분류되면(해당 없음 구간이 끊기면) 모든 기록을 지우고 `offTopic`은 `null`이 된다. 이후 새 구간이 60초에 닿으면 1번부터 다시 시작한다.

## 3. 보드의 offTopic 칸

`offTopic`은 보드의 맨 위 칸이다(`agendas[]` 안이 아니다). 제안이 없으면 `null`이다.

```json
"offTopic": {
  "stage": "SUGGEST",
  "detectedAt": "2026-10-20T05:21:00Z",
  "detectedAtMs": 1260000,
  "suggestedTitle": "채용 계획",
  "evidenceSeqs": [55, 56, 57]
}
```

| 칸 | 타입 | 설명 |
|---|---|---|
| `stage` | 문자열 | `SUGGEST`(새 안건 등록 제안) 또는 `LONG`("지금 다른 이야기를 하고 있다" 알림) |
| `detectedAt` | 문자열 | 이 구간의 제안을 처음 낸 서버 시각 (UTC, ISO 8601). `LONG`에서도 처음 값을 유지한다 |
| `detectedAtMs` | 정수 | 같은 시점의 회의 음성 시간(ms). 경과 시간을 화면이 `detectedAt`이나 이 값을 기준으로 직접 계산할 수 있다 |
| `suggestedTitle` | 문자열 또는 null | 제안하는 새 안건 제목. 모델이 만들지 못했거나 검증을 통과하지 못했으면 `null`이며 이때도 제안은 나간다 |
| `evidenceSeqs` | 정수 배열 | 제목의 근거 전사 줄 번호. 제목이 `null`이면 빈 배열 |

- **경과 시간(`durationSec`)은 보내지 않는다.** 값이 초마다 바뀌면 보드가 매번 바뀌어 전송 빈도 규칙(바뀔 때만, 회의당 초당 1회 이하)을 지킬 수 없다. 화면이 `detectedAt`을 기준으로 계산한다. 연동 API 초안 3.2에 있던 `durationSec`을 뺀 것이라 확인이 필요하다 (11장).
- 보드는 `offTopic`이 바뀔 때도 다시 보낸다. `SUGGEST` → `null` → `LONG` → `null` 순으로 바뀐다.
- 제안이 처음 나가는 보드에는 제목 만들기가 끝난 결과가 담긴다 (같은 처리 흐름에서 제목을 만든 뒤 보드를 보낸다). 제목을 만들지 못하면 `null`로 나가고, 나중에 채워 다시 보내지 않는다.
- 회의가 끝나면(`end`) 마지막 보드의 `offTopic`은 `null`이다.

## 4. 감지 규칙

모델 없이 분류 결과만 읽어서 정한다.

| 규칙 | 내용 |
|---|---|
| 세는 줄 | 분류 결과가 "해당 없음"인 줄. 사람이 고친 분류가 있으면 고친 값을 쓴다. 삭제된 안건으로 분류됐던 줄도 해당 없음으로 본다 |
| 구간 길이 | 구간의 첫 줄 시작부터 마지막 줄 끝까지(음성 시간). 마지막 줄 뒤의 침묵은 포함하지 않는다. `resume`의 `atMs`가 `pause` 값에서 이어지므로(`input-contract.md` 4장) 일시정지 시간은 포함되지 않는다고 본다. 줄 시각이 같은 시계를 쓰는지는 실제 연동 때 확인한다 |
| 연속 | 엄격하다. 구간 사이에 안건 줄이 하나라도 분류되면 처음부터 다시 센다 |
| 건너뛰는 줄 | 맞장구, 간투사, 낮은 확신도 줄은 구간을 끊지도 길이를 늘리지도 않는다. 아직 분류하지 못한 줄도 건너뛴다 |
| 제안 시간 | 60초 이상 (`AGENDA_OFFTOPIC_SEC`). 59초는 제안하지 않는다 |
| 재알림 시간 | 무시한 시각부터 180초 이상 (`AGENDA_OFFTOPIC_LONG_SEC`) |
| 같은 주제 판정 | 하지 않는다. 해당 없음이 끊기지 않고 이어지면 같은 이야기로 본다 (6장 한계) |
| 현재 안건 | 바꾸지 않는다. `currentAgendaId`는 해당 없음이 길어져도 마지막으로 연결된 안건이다 |
| 재알림 횟수 | 구간당 `SUGGEST` 한 번, `LONG` 한 번이다. `LONG`을 무시하면 그 구간에서는 더 알리지 않는다 |
| 등록 이전 줄 | 새 안건으로 옮기지 않는다. 등록 이후 발언만 새 안건에 분류된다 |

## 5. 제안을 무시했다는 알림 받기 (백엔드 → ai-service)

사용자가 `SUGGEST`나 `LONG` 알림을 닫을 때 백엔드가 알린다.

```
POST /internal/meetings/{meetingId}/off-topic-actions
```

### 5.1 본문

| 필드 | 타입 | 설명 |
|---|---|---|
| `meetingId` | 문자열 또는 정수 | 주소의 값과 같아야 한다 |
| `action` | 문자열 | `dismiss`만 받는다 |
| `rev` | 정수 | 회의 안에서 계속 커진다. 이미 받은 값 이하이면 `stale`로 무시한다 |
| `atMs` | 정수, 선택 | 무시한 시각(회의 음성 시간, ms). 없으면 받은 시점의 음성 시간을 쓴다. 재시작 복구 때 백엔드가 보관해 둔 값을 다시 보낼 때만 쓴다 |

### 5.2 처리

- `atMs`가 없는데 지금 떠 있는 제안(`SUGGEST`, `LONG`)이 없으면 받지 않고 `not_active`로 답한다.
- `atMs`가 있으면 구간이 아직 다시 만들어지기 전이어도 보관한다. 현재 구간의 시작 + 60초(`AGENDA_OFFTOPIC_SEC`)보다 이른 값은 지난 구간의 무시라서 쓰지 않는다.
- 받으면 다음 주기에 `offTopic`이 바뀐 보드를 보낸다. `SUGGEST`를 무시하면 `null`, `LONG`을 무시하면 이 구간에서는 `null`로 남는다.
- 등록은 별도 요청이 없다. 안건 목록 전체를 다시 받으면(`agenda-contract.md` 4장) 처음 보는 안건이 있는지로 안다. 등록과 상관없이 안건이 추가돼도 제안을 거둔다.

### 5.3 응답

| 상황 | 응답 |
|---|---|
| 반영함 | `{"accepted": true, "result": "accepted", "applied": true}` |
| `rev`가 오래됨 | `{"accepted": true, "result": "stale", "applied": false}` |
| 떠 있는 제안이 없음 | `{"accepted": true, "result": "not_active", "applied": false}` |
| 끝난 회의 | `{"accepted": false, "result": "ignored", "reason": "ended"}` |
| 형식 오류 | 400 `INVALID_INPUT` |
| 서버 준비 안 됨 | 503 `NOT_READY` |

## 6. 제목 만들기

- 구간이 처음 `SUGGEST`나 `LONG`이 될 때 모델을 **한 번** 부른다(`ai.task` 값 `agenda_offtopic`). 구간이 이어지는 동안은 다시 만들지 않는다. 구간이 끊긴 뒤 새 구간에서 다시 만든다.
- 입력은 그 구간의 원문 줄(맞장구, 간투사, 낮은 확신도 줄 제외, 최근 40줄까지)과 등록된 안건 제목이다. 이전에 만든 요약이나 항목은 쓰지 않는다.
- 모델은 제목과 근거 줄을 낸다. 근거는 기존 검증기(`meeting_summary.validate_items`)로 확인하고, 제목이 30자를 넘거나 등록된 안건과 같으면 오류를 알려 1회 더 부른다. 그래도 통과하지 못하면 제목을 `null`로 두고 제안은 그대로 낸다.
- 모델이 "하나의 주제로 모이지 않는다"고 답하면(`title: null`) 거부로 세지 않고 제목 없이 낸다.
- 호출이 연속 3번 실패하거나 회의당 호출 상한(기본 20)에 닿으면 제목 만들기만 멈춘다. 감지와 보드 전송은 계속된다.
- 제목은 로그와 상태 조회에 남기지 않는다.

## 7. 설정

| 환경변수 | 뜻 | 기본 |
|---|---|---|
| `AGENDA_OFFTOPIC_SEC` | 해당 없음이 이만큼 이어지면 새 안건 제안(초, 음성 시간) | 60 |
| `AGENDA_OFFTOPIC_LONG_SEC` | 제안을 무시한 뒤 이만큼 더 이어지면 "지금 다른 이야기" 알림(초) | 180 |
| `MAX_AGENDA_OFFTOPIC_CALLS_PER_MEETING` | 회의당 제목 호출 상한 | 20 |

값은 모두 1 이상의 정수여야 하며 아니면 서버가 뜨지 않는다. 제안 시간 60초는 명세서 REQ-091(1분), 재알림 180초는 REQ-092(무시한 뒤 3분)에 맞춘 값이다(2026-10-28 변경. 이전 제안 시간은 PRD 3분이었다). 호출 상한은 제안값이다.

## 8. 토큰 지표

모델을 부를 때 `ai.task` 값은 `agenda_offtopic`이다.

## 9. 복구

- AI 서버가 재시작하면 구간은 줄 묶음 복구(`input-contract.md` 8장)로 분류가 다시 만들어지는 대로 다시 계산된다.
- **무시 기록은 메모리에만 있어 재시작하면 사라진다.** 백엔드가 보관해 둔 무시 기록(`rev`, `atMs`)을 줄 묶음보다 먼저 5장의 요청으로 다시 보내 주기를 요청한다. 순서가 바뀌어도 반영된다.
- 보내 주지 않으면 이미 무시한 제안이 다시 뜰 수 있다.

## 10. 이번 범위에서 하지 않는 것

| 하지 않는 것 | 이유 |
|---|---|
| 해당 없음 구간 안에서 주제가 바뀌었는지 비교 | 모델 호출이 늘고 기준이 불명확하다. 기획 확인 필요 |
| 등록 이전의 해당 없음 줄을 새 안건으로 옮기기 | PRD가 "이후 발언"이라고 했고, AI-02는 이미 분류한 줄을 다시 분류하지 않는다 |
| 새 안건을 AI 서버가 직접 만들기 | 안건 목록은 백엔드가 가진다 |
| 현재 안건을 해당 없음으로 바꾸기 | AI-04의 "논의 중"과 맞지 않는다 |
| 등록 요청을 따로 받기 | 안건 목록 갱신으로 갈음한다 |
| `durationSec` 계속 갱신 | 3장 |

한계

- 감지는 AI-02의 해당 없음 분류에 전적으로 기댄다. 안건 제목이 넓어 잡담이 안건으로 분류되면 감지를 놓친다.
- 분류가 한 줄 틀리면 구간이 끊긴다 (엄격한 연속 판정).
- 줄 묶음(10초) 단위로 처리하므로, 구간이 제안 시간(기본 60초)에 닿는 줄과 구간을 끝내는 안건 줄이 같은 묶음에 들어오면 그 묶음을 처리할 때는 이미 구간이 끝나 있어 제안이 나오지 않는다. 60초 경계 합성 시험(2026-10-28)에서 60~65초 구간 5개 중 1개(61.0초)를 이렇게 놓쳤고 74.89초 이상 구간 8개는 모두 제안이 나왔다. 이미 끝난 잡담에 제안을 띄우지 않는 쪽이라 고치지 않았다. 제안 시각은 구간이 제안 시간에 닿은 뒤 처음 처리되는 묶음의 시각이다(시험한 제안 12개 모두 계산한 기대 시각과 같았다).
- 회의 시작 직후의 잡담도 어느 안건에도 분류되지 않았다면 구간으로 센다.
- 등록한 새 안건의 요약은 등록 이전 줄을 쓰지 않아 한동안 비어 보일 수 있다.

### 11.1 안건 보드(연동 API 초안 3.2)와의 관계

| 내용 | 가는 곳 | 구현 시점 |
|---|---|---|
| 안건별 요약 | 보드 `agendas[].summary` | AI-03 |
| 안건 상태와 판정 근거 | 보드 `agendas[].status`, `statusReason` | AI-04 |
| 의견·근거, 할 일 | 보드 `agendas[].opinions`, `todos` | AI-05 |
| 주제 변경 | 보드 `offTopic` | AI-06 |

연동 API 초안 3.2와 다른 점은 `offTopic`의 `stage`, `detectedAtMs`가 늘고 `durationSec`이 빠진 것이다. 나머지 칸은 초안을 그대로 쓴다.

## 12. 예시 파일

| 파일 | 내용 |
|---|---|
| `examples/api/agenda-board-offtopic-put.json` | 안건 보드 한 번의 본문 (`offTopic`이 `SUGGEST`인 상태) |
