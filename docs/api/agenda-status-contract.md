# AI 서버 안건 상태 판정 형식 (AI-04) v0.1 초안

> 안건 상태 판정(AI-04)을 안건 보드(연동 API 초안 3.2)에 담아 보내는 방식을 다룬다. 아직 cn 팀과 확인하기 전의 AI 쪽 제안이다. 확정되면 이 문서를 최신 전체본 하나로 교체한다.
> 안건 목록과 줄별 분류는 `agenda-contract.md`, 안건별 요약과 보드 전체 모양은 `agenda-summary-contract.md`에 있다.

- 근거: PRD v0.1 AI-04, 요구사항 REQ-076·078·086, 연동 API 초안 3.2 (안건 보드 결과)
- 예시 파일: `examples/api/agenda-board-put.json`
- 평가: 평가 도구와 기준은 `summary/eval_agenda_status.py`, 결과는 평가 뒤 `docs/eval/`에 둔다

## 1. 목적과 범위

| 구분 | 내용 |
|---|---|
| 목적 | 안건마다 "아직 안 다룸 / 논의 중 / 결정 / 미결 / 결정 확인 필요" 중 하나와 그렇게 본 근거를 보여 준다 |
| 다루는 것 | 안건 보드 `agendas[].status` 채우기, 판정 근거 `agendas[].statusReason` |
| 이 문서 밖 | 의견·할 일(AI-05), 주제 변경 감지(AI-06), 오늘 회의 요약(AI-08, 이 상태를 읽어 "결정된 사항"을 만든다) |

## 2. 상태 값

| 값 | 화면 표현 | 정하는 방법 |
|---|---|---|
| `NOT_STARTED` | 아직 안 다룸 | 안건에 연결된 줄이 없다 (모델 없이) |
| `DISCUSSING` | 논의 중 | 줄이 있고 결정이 없고, 이 안건이 현재 안건이다 (모델 없이) |
| `DECIDED` | 결정 | 모델이 "결정할 사항에 대한 답과 합의 표현이 있다"고 판정하고 근거 줄이 검증을 통과했다 |
| `UNDECIDED` | 미결 | 줄이 있고 결정이 없고, 다른 안건으로 넘어갔거나 회의가 끝났다 (모델 없이) |
| `DECISION_CHECK` | 결정 확인 필요 | 모델이 "답처럼 보이는 말은 있지만 확신이 낮다"고 판정하고 근거 줄이 검증을 통과했다 |

- 연동 API 초안 3.2의 값은 앞의 네 개이다. `DECISION_CHECK`는 PRD AI-04의 예외 "결정 확인 필요"(REQ-086)를 상태로 나타내려는 새 값이며 이름은 제안이다 (11장).
- 결정이 아닌 상태를 모델이 정하지 않는 이유: 판정 모델이 맞히기 어려운 것은 "결정이 났는가" 하나뿐이고, 나머지는 현재 안건 정보로 정할 수 있다.
- 현재 안건이 바뀌면 이전 안건의 `DISCUSSING`은 `UNDECIDED`로 바뀐다. 회의가 끝나면 `DECIDED`, `DECISION_CHECK`가 아닌 줄 있는 안건은 모두 `UNDECIDED`이다.

## 3. 보드에 담기는 모양

기존 보드(`agenda-summary-contract.md` 4장)의 `status`가 위 값으로 채워지고, 안건마다 `statusReason`이 하나 늘어난다.

```json
{
  "agendaId": 101,
  "status": "DECIDED",
  "statusReason": {"text": "1차 배포를 다음 주 목요일로 정하고 참석자가 동의함", "evidenceSeqs": [42, 43]},
  "summary": [],
  "opinions": []
}
```

| 칸 | 내용 |
|---|---|
| `statusReason` | 줄이 없는 안건(`NOT_STARTED`)은 `null`. 아니면 `text`(한 문장)와 `evidenceSeqs`(전사 줄 번호) |
| `DECIDED`, `DECISION_CHECK`의 `statusReason` | 모델이 쓴 이유와 근거 줄. 근거 없이는 이 두 상태를 내지 않는다 |
| `DISCUSSING`, `UNDECIDED`의 `statusReason` | 규칙으로 만든 문장(연결된 발언 줄 수와 마지막 줄 번호) |

## 4. 판정 시점

- 줄이 새로 붙은 안건은 새 줄이 2개 이상이면 바로, 1개면 60초(음성 시간) 뒤에 판정한다 (안건별 요약과 같은 규칙).
- 줄이 빠져나갔거나 글이 바뀐 안건(사람이 고친 분류 포함)은 기다리지 않고 바로 다시 판정한다.
- 결정(`DECIDED`)과 확인 필요(`DECISION_CHECK`)인 안건도 새 줄이 오면 다시 판정한다.
- 회의가 끝나면(`end`) 바뀐 안건을 한 번 더 판정하고 나머지를 `UNDECIDED`로 확정한다.
- 사용자가 회의 종료 버튼을 누르면(AI-07, `agenda-leftover-contract.md`) 새 줄이 1개일 때 기다리는 규칙을 한 번 건너뛰고 판정한다. 이때는 상태를 **확정하지 않는다**. 미결 안건 목록은 종료를 확정한다고 가정한 상태(논의 중인 안건은 미결)로 만들고 판정기의 상태는 바꾸지 않아서, 이어서 논의하기로 돌아가면 보드의 상태는 그대로 논의 중이다.
- 서버 안에서는 분류 → 상태 판정 → 안건별 요약 → 보드 전송 순서로 한 흐름에서 처리한다. 보드는 상태가 바뀔 때도 다시 보낸다.

## 5. 모델에 주는 입력

| 구분 | 내용 |
|---|---|
| 넣는 것 | 안건 제목, 결정할 사항, 그 안건에 연결된 전사 줄(번호, 시각, 글) |
| 맞장구 줄 | 합의 표현일 수 있어 넣는다. 안건 표시가 없으므로 바로 앞에 분류된 줄의 안건에 붙인다 (앞 줄 끝에서 10초 이내, 그 사이에 해당 없음 줄이 없을 때) |
| 빼는 것 | 간투사 줄, 낮은 확신도 줄, 분류하지 못한 줄, 안건별 요약 문장(요약 위에 쌓지 않는다) |

## 6. 검증

- `DECIDED`, `DECISION_CHECK`는 이유(`reason`)가 있고 근거 구간이 입력의 줄 번호 안에 있어야 한다. 이유 문장은 요약과 같은 검증기(인용, 숫자, STT 불확실 표시)를 지난다.
- 통과하지 못하면 오류를 알려 1회 더 부르고, 그래도 통과하지 못하면 판정하지 않고(결정 없음) 넘어간다. 이때는 연속 실패로 세지 않는다.
- 호출이 연속 3번 실패하거나 회의당 호출 상한(기본 300)에 닿으면 이 회의의 모델 판정만 멈춘다. 이미 낸 판정과 규칙 판정은 계속 낸다.

## 7. 설정

| 환경변수 | 설명 | 기본값 |
|---|---|---|
| `AGENDA_STATUS_REFRESH_SEC` | 새 줄이 1개뿐일 때 판정을 기다리는 시간(음성 시간 초) | 60 |
| `MAX_AGENDA_STATUS_CALLS_PER_MEETING` | 회의당 상태 판정 호출 상한 (비용을 추정한 뒤 다시 정함) | 300 |

모델은 요약과 같은 `LLM_PROVIDER`, `LLM_MODEL`을 쓴다. `LLM_PROVIDER=echo`이면 모델을 부르지 않는다.

## 8. 토큰 지표

모델 호출은 `ai.task=agenda_status`로 `gen_ai.client.token.usage`에 남는다.

## 9. 사람이 고친 상태

받지 않는다. PRD와 요구사항에 상태를 사람이 고치는 기능이 없다 (REQ-079의 "수동 수정"은 안건 전환이다). 연동 API 초안 3.2는 백엔드 값이 우선이라고 되어 있어, 필요해지면 백엔드가 사람이 고친 상태를 보드에 덮어쓰는 방식을 먼저 확인한다 (11장).

## 10. 이번 범위에서 하지 않는 것

| 항목 | 이유 |
|---|---|
| 회의가 끝난 뒤 "이어서 논의하기"(REQ-084) 처리 | 끝난 뒤 알림과 다시 여는 방식이 정해지지 않았다 |
| 안건 여러 개에 걸친 결정 | 줄은 안건 하나에만 연결된다 |
| 모델에 요약 문장 주기 | 요약의 오류가 판정으로 번지는 것을 피한다 |

## 11. 협의 상태

| 항목 | 상태 |
|---|---|
| 상태에 `DECISION_CHECK`를 새로 둔다 | AI 제안, 기획·cn 팀 확인 필요 |
| 보드 안건에 `statusReason`(`text`, `evidenceSeqs`)을 둔다 | AI 제안, cn 팀 확인 필요 |
| 사람이 고친 상태를 받을지, 받는다면 전달 방식 | 기획 확인 필요 (범위), 이후 cn 팀 |
| 회의가 끝나면 결정이 아닌 안건은 `UNDECIDED` | AI 제안, 기획 확인 필요 |
| 끝난 뒤 "이어서 논의하기" 알림 방식 | AI-07에서 종료 버튼 알림(`end-requests`)으로 대신하는 방식을 제안했다(`agenda-leftover-contract.md`), cn 팀 확인 필요 |
| 지표 `ai.task` 값 `agenda_status` | cn 팀 확인 필요 |
| 판정 시점(새 줄 2개 또는 60초), 호출 상한 300, 맞장구 붙이는 간격 10초 | 제안값, 평가 뒤 조정 |
