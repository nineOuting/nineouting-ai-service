# AI 서버 회의록 양식 가져오기 (REQ-195, SCRUM-289) v0.1 초안

> 사용자가 가지고 있는 회의록 양식 파일(PDF)을 올리면 항목을 읽어 새 양식으로 만들고, 양식 편집 화면에서 확인하게 하는 기능의 AI 서버 쪽 제안이다.
> **모듈, 손 시험 도구, 서버 주소(3.1)를 구현했다.** 서버 주소의 요청·응답 모양은 백엔드와 합의한 것이 아니라 **AI 쪽이 정해서 통보하는 제안**이다(백엔드 답변이 늦어 먼저 구현). 다르게 필요하면 알려 주면 입구 부분만 고친다. 아래 "정할 것"의 값도 AI 쪽 제안이며 바뀔 수 있다. 확정되면 이 문서를 최신 전체본 하나로 교체한다.
> 양식의 모양은 회의록 초안 명세 `minutes-draft-contract.md` 5.8 TemplateField를 따른다.

- 근거: 요구사항 REQ-195 (양식 가져오기, 비고: "파일 분석 기능 필요(AI팀 또는 문서 분석). 지금은 화면만 있고 항상 '분석하지 못했어요' 표시"), 노션 "기능 추가 제안" 3번
- 코드: `minutes/template_import.py`, 지시문 `minutes/prompts/template_import/v1.md`, 손 시험 `python -m minutes.try_template_import`
- 시험: `pytest minutes/tests/test_template_import.py` (모델 없음)

## 1. 범위

| 구분 | 내용 |
|---|---|
| 하는 것 | **글이 있는 파일** 한 개(PDF, 워드 docx, 엑셀 xlsx, 글 파일 txt·md·csv)에서 양식 항목(제목, 기록 방식, 표의 열 개수, 설명)과 머리글·바닥글을 읽어 `template.fields`, `header`, `footer` 모양으로 돌려준다. 형식은 확장자가 아니라 파일 내용으로 판단한다 |
| 하지 않는 것 | 스캔 PDF·이미지(글자를 못 뽑는 파일), 옛 doc·xls, 한글(hwp·hwpx), 파워포인트(pptx)는 `unsupported_format`(스캔 PDF는 `no_text`)으로 거절한다. 배경 이미지·글꼴·칸 크기 같은 서식 재현, 표의 칸 선 읽기도 하지 않는다 |
| 아직 정하지 않음 | 한글(hwp·hwpx)과 이미지 지원 여부. hwpx는 zip 안의 XML이라 읽을 수 있어 보이지만 아직 시험하지 않았다 (미확인). hwp(옛 형식)는 별도 라이브러리가 필요하다 |

## 2. 처리 순서

1. 파일 판별과 읽기: PDF, 워드, 엑셀, 글 파일이 아니면 `unsupported_format`, 암호 파일은 `encrypted`, 쪽이 너무 많거나 글이 너무 길면 `too_large`, 글이 없으면 `no_text` (RAG 업로드 문서와 같은 코드)
2. 글을 줄로 꺼내 줄마다 번호(L1, L2, ...)를 단다. 머리글·바닥글은 지우지 않는다. 워드·엑셀·글 파일은 한 쪽으로 보고, 워드의 머리글·바닥글은 맨 앞과 맨 뒤 줄로 넣는다. 표는 칸을 ` | `로 이어 한 줄로 쓴다 (워드·엑셀은 칸 경계를 알 수 있어 PDF보다 열 개수를 세기 쉽다).
3. AI에게 줄 번호가 붙은 글을 주고 아래를 받는다. 모델은 **글을 쓰지 않고 줄 번호만 고른다.**

```json
{"header": [1], "footer": [36],
 "fields": [{"ref": 3, "title": "논의 내용", "type": "free", "columns": null, "descriptionRefs": [4]},
            {"ref": 8, "title": "할 일", "type": "table", "columns": 3, "descriptionRefs": []}]}
```

4. 코드가 검사한다. 걸리면 이유를 붙여 다시 시킨다 (최대 2번).

| 검사 | 어기면 |
|---|---|
| `ref`, `descriptionRefs`, `header`, `footer`의 줄 번호가 있는 줄이다 | 다시 시킴 |
| `title`이 그 `ref` 줄의 글에 있다 (띄어쓰기·대소문자 무시). 한 줄에 칸 이름이 여럿이면("회의명 일시") 같은 `ref`를 쓰고 줄에 나온 순서대로 | 다시 시킴 |
| 항목은 1~20개, 문서에 나온 순서, 제목이 겹치지 않음, 제목 1~100자 | 다시 시킴 |
| `type`이 `free`·`list`·`checklist`·`table` 중 하나, 표이면 `columns`가 센 열 개수(1~12의 정수) | 다시 시킴 |
| 표의 열이 8보다 많다 (명세 5.8 상한) | 8로 자르고 경고 `COLUMNS_CAPPED`에 센 값(`detected`)을 남김 |
| `header`는 첫 쪽의 위 5줄, `footer`는 마지막 쪽의 아래 5줄 안에 있다 | 다시 시킴 |
| 설명 줄이 항목 제목·머리글·바닥글과 겹치지 않는다, 설명 2,000자 이하 | 다시 시킴 |
| 체크리스트인데 그 항목 안에 체크박스 글자(☐ □ [ ])가 없다 | 종류는 그대로 두고 경고 `CHECKLIST_NO_BOX` |
| 설명 줄에 빈칸(`____`)이 있다 (양식 본문의 서식 문장) | 설명에서 빼고 경고 `DESCRIPTION_DROPPED` |
| 줄 번호를 `3`, `"3"`, `"L3"`로 써도 읽는다 | - |
| 항목을 하나도 못 찾았다 | 실패 `NO_FIELDS` |

5. `description`, `header`, `footer`는 AI가 쓴 글이 아니라 **AI가 고른 줄의 원문을 코드가 이어 붙인 것**이다. 지어낸 글이 들어갈 수 없다.

## 3. 결과 (모듈이 돌려주는 값)

성공:

```json
{"fields": [{"title": "논의 내용", "type": "free", "description": "※ 안건별로 적는다", "aiFill": true},
            {"title": "할 일", "type": "table", "columns": 3, "aiFill": true}],
 "header": "나인아웃팅 회의록", "footer": "- 2 -",
 "warnings": [{"code": "CHECKLIST_NO_BOX", "title": "확인 사항"}, {"code": "COLUMNS_CAPPED", "title": "이슈 / 리스크", "detected": 8}]}
```

- `fields`의 항목 모양은 명세 5.8과 같다. `columns`는 표일 때만, `description`은 설명이 있을 때만 들어간다.
- `aiFill`은 모두 `true`로 둔다 (정할 것 3번).
- 실패는 오류 코드 하나: `unsupported_format`, `encrypted`, `too_large`, `no_text`, `NO_FIELDS`, `CHECK_FAILED`, `LLM_TIMEOUT`, `LLM_FAILED`. 양식 글은 오류 글과 로그에 남기지 않는다.

## 3.1 서버 주소 (구현함, 형식은 AI 쪽 제안)

```
POST /internal/minutes/template-imports      동기. 호출 1번에 보통 4~25초
```

요청 (JSON)

```json
{"requestId": "6f1c2a9e-1b7d-4c55-9d1a-3a8e0f4b2c11", "fileUrl": "https://<허용한 저장소>/templates/form.pdf?X-Amz-Signature=..."}
```

- `requestId`는 선택이다(1~200자, 로그와 응답에 그대로 쓴다). `fileUrl`은 서명 주소다. AI 서버가 내려받는다(디스크에 쓰지 않는다, 리다이렉트를 따라가지 않는다).
- 헤더 `X-Request-Id`가 있으면 로그에 남긴다(회의록 초안과 같다).
- 파일 크기 상한은 20MB(환경변수 `MINUTES_IMPORT_MAX_MB`), 쪽·글자 상한은 2장의 값이다.

응답

| 상태 | 본문 | 의미 |
|---|---|---|
| 200 | `{"requestId", "status": "SUCCEEDED", "fields": [...], "header", "footer", "warnings": [...]}` | 3장의 결과 그대로. `requestId`는 요청에 넣었을 때만 돌려준다 |
| 200 | `{"requestId", "status": "FAILED", "errorCode": "..."}` | 파일을 읽지 못했거나 항목을 못 찾음. 코드는 아래 표 |
| 400 | `{"error": "INVALID_INPUT", "detail": "..."}` | 요청 형식 오류, 허용하지 않은 저장소 주소 (오류 글에 주소를 넣지 않는다) |
| 503 | `{"error": "NOT_READY", "detail": "..."}` | AI 설정이나 파일 받기 설정이 준비되지 않음 |
| 503 | `{"error": "BUSY", "detail": "..."}` | 동시에 처리하는 양식이 가득 참(기본 4개). 잠시 뒤 다시 보낸다 |

`errorCode`

| 코드 | 의미 | 화면에서 하면 좋은 안내 |
|---|---|---|
| `unsupported_format` | 읽을 수 없는 형식(한글, 파워포인트, 이미지, 옛 doc·xls 등) | 다른 형식의 파일로 올리게 안내 |
| `encrypted` | 암호가 걸린 파일 | 암호를 풀고 다시 올리게 안내 |
| `too_large` | 파일, 쪽, 글자 상한을 넘음 | 줄여서 올리게 안내 |
| `no_text` | 글을 뽑을 수 없음(스캔·이미지 PDF) | 글이 있는 파일로 올리게 안내 |
| `NO_FIELDS`, `CHECK_FAILED` | 항목을 못 찾았거나 검사를 통과하는 답을 못 받음 | 직접 만들기 안내 |
| `LLM_TIMEOUT`, `LLM_FAILED` | AI 호출이 시간 초과이거나 실패 | 잠시 뒤 다시 시도 안내 |
| `url_expired` | 서명 주소가 만료됨 | 백엔드가 새 서명 주소로 다시 호출 (사용자에게는 일반 실패) |
| `download_failed` | 파일을 받지 못함(허용하지 않은 주소 등) | 백엔드가 확인, 사용자에게는 일반 실패 |
| `internal_error` | 예상 못 한 오류 | 일반 실패 |

- 시간: 호출 1번에 보통 4~25초. 검사에 걸려 다시 시키면 최대 3번까지 부르고, AI 호출 하나는 30초(`MINUTES_IMPORT_TIMEOUT_S`)에서 끊는다. 가장 나쁜 경우 약 2분이므로 **호출하는 쪽의 시간 제한은 2분 이상**으로 두기를 제안한다.
- 허용 저장소: RAG 업로드와 같은 `RAG_UPLOAD_ALLOWED_HOSTS`(DEV는 `nineouting-dev-files.s3.ap-northeast-2.amazonaws.com`). 양식 파일을 올리는 저장소가 다르면 알려 주어야 한다.
- 로그에는 요청 번호, 결과, 오류 코드, 호출 횟수, 토큰 수, 걸린 시간만 남긴다. 서명 주소와 양식 글은 남기지 않는다.
- 서버 간 인증은 회의록 초안과 같은 자리에 있고 지금은 통과시킨다(백엔드 방식이 정해지면 같이 적용).

## 4. 정할 것 (백엔드, 기획)

| # | 정할 것 | AI 쪽 제안 |
|---|---|---|
| 1 | 파일 전달 | **3.1에 이 제안대로 구현함.** RAG 업로드 문서처럼 서명 주소(`fileUrl`)를 받아 서버가 내려받는다 (허용 저장소 설정 필요). 직접 올리는 방식은 AI 서버가 파일을 받는 주소를 새로 만들어야 한다 |
| 2 | 동기·비동기 | **3.1에 동기로 구현함.** 호출 1번이면 끝나고 글이 짧아 한 번에 답하는 동기가 간단하다. 시간 제한과 대기열 사용 여부는 실제 시간을 재 본 뒤 정한다 (아직 안 잼) |
| 3 | `aiFill` | 가져온 항목을 AI가 채울지(`true`) 사용자가 채울지. 양식에는 보통 AI가 채우는 항목이 대부분이라 `true`로 두고 사용자가 화면에서 바꾸는 것을 제안한다 |
| 4 | 읽지 못했을 때 화면 | 실패 코드별 문구(스캔 PDF라 읽을 수 없음, 항목을 못 찾음 등). 일부만 읽은 경우는 경고(`warnings`)로 알린다 |
| 5 | 이름이 겹치는 양식 | 항목 제목이 겹치면 AI가 다시 읽게 한다. 같은 이름이 꼭 필요한 양식은 지원하지 않는다 |
| 6 | PDF 외 형식 | **워드, 엑셀, txt, md, csv는 AI 서버에서 읽을 수 있게 했다** (합성 양식 5개 × 5형식 시험). 한글(hwp·hwpx), 이미지, 파워포인트를 지원할지 |
| 7 | 표 열 상한 | **AI 서버는 8로 올렸다** (프론트 양식 편집 화면 상한과 같다). minutes-service의 `DraftService`가 AI에 보낼 때 6으로 자르는 줄(`Math.clamp(cols, 1, 6)`)도 8로 맞춰야 한다 |
| 8 | 회의 정보 칸 | 문서번호, 회의명, 일시 등은 회의록 화면이 따로 채운다고 보고 항목에서 뺀다 (기획 확인 전) |
| 9 | 파일 상한 | 지금 10쪽, 글 2만 자는 AI 쪽 제안값 (실제 양식 샘플로 확인 전) |

## 5. 다른 파일 형식 시험 (2026-11-18)

같은 합성 양식 5개를 워드, 엑셀, txt, md, csv로 만들어 실제 모델로 읽었다 (25개 파일).

| 형식 | 항목 재현율 | 정밀도 | 표 열 개수 | 호출 |
|---|---|---|---|---|
| docx | 23/23 | 25/25 | 3/3 | 5 (파일당 1번) |
| xlsx | 23/23 | 23/23 | 3/3 | 5 |
| txt | 23/23 | 25/26 | 3/3 | 5 |
| md | 23/23 | 26/26 | 3/3 | 5 |
| csv | 23/23 | 23/23 | 3/3 | 5 |

**복잡한 양식으로 다시** (PDF 시험 때 쓴 정기업무, 프로젝트, 이사회 의사록, 고객 미팅, 장애 대응 5개를 같은 구조로 5개 형식으로 만들었다. 결재란(병합 칸), 체크박스, 5~10열 표, 의안 반복, 워드 자동 번호 포함. 25개 파일)

| 형식 | 항목 재현율 | 정밀도 | 표 열 개수 | 호출 | 토큰 입력 / 출력 |
|---|---|---|---|---|---|
| docx | 35/35 | 35/39 | 20/20 | 5 (파일당 1번) | 10.1K / 4.3K |
| xlsx | 35/35 | 35/39 | 20/20 | 5 | 10.5K / 5.5K |
| txt | 35/35 | 40/44 | 20/20 | 5 | 10.5K / 4.8K |
| md | 35/35 | 35/37 | 20/20 | 5 | 10.5K / 3.9K |
| csv | 35/35 | 35/39 | 20/20 | 5 | 10.7K / 4.8K |

- 정밀도에서 정답표에 없다고 센 것은 이사회 의사록의 `배석자`, `감사 참석`, `제 1 호 의안`, `제 2 호 의안`이다. 실제 양식의 제목이라 틀렸다고 보기 어렵고 정답표가 그 구조를 정하지 않은 탓이다.
- 마크다운 표는 처음에 6열을 7열로 세는 오류가 반복돼(표 열 18/20), 양 끝의 `|`와 `|---|` 구분 줄을 빼 워드·엑셀 표와 같은 모양으로 정리해 읽게 했다. 그 뒤 20/20이다.
- 워드의 세로로 병합된 칸(결재란)은 표 전체에서 한 번만 읽는다.
- 워드의 자동 번호 매기기로 번호를 매긴 제목(`성원 보고 및 개회 선언`)은 번호 없이 읽혔지만 항목 제목은 맞게 나왔다.

- 정답표는 AI 쪽이 만든 초안이고 양식은 모두 합성이다. 파이썬 라이브러리로 만든 파일이라 **실제 워드·엑셀 파일의 변칙(글상자, 자동 번호 매기기, 병합 칸, 중첩 표)은 시험하지 못했다.**
- 워드의 자동 번호("1.", "가.")는 글자로 저장되지 않아 읽지 못한다. 번호 없이도 항목 제목은 읽힌다.
- 한글(hwp·hwpx), 이미지, 파워포인트는 시험하지 않았다.

## 6. 아직 재 보지 않은 것

- 항목 재현율 같은 수치. 합성 양식 5개와 복잡한 양식 5개로 눈으로만 확인했다 (호출 1번, 7~15초, 출력 700~1,600 토큰). 의안이 반복되는 구조(이사회 의사록)는 항목으로 나오지 않는다.
- 표는 글 추출 결과가 칸마다 쪼개지지 않고 한 줄("항목 금액 비고")로 나온다 (합성 PDF로 확인). 열 개수는 머리 행을 보고 AI가 센다. 선이 없는 표나 병합 칸에서 틀릴 수 있다.
- 호출 시간과 비용. 모델은 1번 부르고, 검사에 걸리면 최대 2번 더 부른다.
- 쪽마다 반복되는 머리글을 첫 쪽 것만 `header`로 쓴다. 쪽마다 다른 머리글은 다루지 않는다.
