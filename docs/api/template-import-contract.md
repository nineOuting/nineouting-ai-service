# AI 서버 회의록 양식 가져오기 (REQ-195, SCRUM-289) v0.1 초안

> 사용자가 가지고 있는 회의록 양식 파일(PDF)을 올리면 항목을 읽어 새 양식으로 만들고, 양식 편집 화면에서 확인하게 하는 기능의 AI 서버 쪽 제안이다.
> **모듈과 손 시험 도구만 구현했고 서버 주소는 없다.** 파일을 어떻게 주고받는지, 결과를 어떻게 돌려주는지는 백엔드와 정하지 않았다. 아래 "정할 것"의 값은 모두 AI 쪽 제안이며 바뀔 수 있다. 확정되면 이 문서를 최신 전체본 하나로 교체한다.
> 양식의 모양은 회의록 초안 명세 `minutes-draft-contract.md` 5.8 TemplateField를 따른다.

- 근거: 요구사항 REQ-195 (양식 가져오기, 비고: "파일 분석 기능 필요(AI팀 또는 문서 분석). 지금은 화면만 있고 항상 '분석하지 못했어요' 표시"), 노션 "기능 추가 제안" 3번
- 코드: `minutes/template_import.py`, 지시문 `minutes/prompts/template_import/v1.md`, 손 시험 `python -m minutes.try_template_import`
- 시험: `pytest minutes/tests/test_template_import.py` (모델 없음)

## 1. 범위

| 구분 | 내용 |
|---|---|
| 하는 것 | **글이 있는 PDF** 한 개에서 양식 항목(제목, 기록 방식, 표의 열 개수, 설명)과 머리글·바닥글을 읽어 `template.fields`, `header`, `footer` 모양으로 돌려준다 |
| 하지 않는 것 | 스캔 PDF(글자를 못 뽑는 파일), docx 등 PDF 외 형식, 배경 이미지·글꼴·칸 크기 같은 서식 재현, 표의 칸 선 읽기 |
| 아직 정하지 않음 | PDF 외 형식 지원 여부 (`rag/`에는 docx·xlsx 로더가 있다) |

## 2. 처리 순서

1. 파일 판별과 읽기: PDF가 아니면 `unsupported_format`, 암호 PDF는 `encrypted`, 쪽이 너무 많거나 글이 너무 길면 `too_large`, 글이 없으면 `no_text` (RAG 업로드 문서와 같은 코드)
2. 쪽마다 글을 줄로 꺼내 줄마다 번호(L1, L2, ...)를 단다. 머리글·바닥글은 지우지 않는다.
3. AI에게 줄 번호가 붙은 글을 주고 아래를 받는다. 모델은 **글을 쓰지 않고 줄 번호만 고른다.**

```json
{"header": [1], "footer": [36],
 "fields": [{"ref": 3, "title": "논의 내용", "type": "free", "columns": null, "descriptionRefs": [4]},
            {"ref": 8, "title": "할 일", "type": "table", "columns": 3, "descriptionRefs": []}]}
```

4. 코드가 검사한다. 걸리면 이유를 붙여 다시 시킨다 (최대 2번).

| 검사 | 어기면 |
|---|---|
| `ref`, `descriptionRefs`, `header`, `footer`의 줄 번호가 있는 줄이다 | 다시 시킴 |
| `title`이 그 `ref` 줄의 글에 있다 (띄어쓰기·대소문자 무시) | 다시 시킴 |
| 항목은 1~20개, 문서에 나온 순서, 같은 줄을 두 번 쓰지 않음, 제목이 겹치지 않음, 제목 1~100자 | 다시 시킴 |
| `type`이 `free`·`list`·`checklist`·`table` 중 하나, 표이면 `columns`가 1~6의 정수 | 다시 시킴 |
| `header`는 첫 쪽의 위 5줄, `footer`는 마지막 쪽의 아래 5줄 안에 있다 | 다시 시킴 |
| 설명 줄이 항목 제목·머리글·바닥글과 겹치지 않는다, 설명 2,000자 이하 | 다시 시킴 |
| 체크리스트인데 그 항목 안에 체크박스 글자(☐ □ [ ])가 없다 | 목록(`list`)으로 낮추고 경고 `CHECKLIST_NO_BOX` |
| 항목을 하나도 못 찾았다 | 실패 `NO_FIELDS` |

5. `description`, `header`, `footer`는 AI가 쓴 글이 아니라 **AI가 고른 줄의 원문을 코드가 이어 붙인 것**이다. 지어낸 글이 들어갈 수 없다.

## 3. 결과 (모듈이 돌려주는 값)

성공:

```json
{"fields": [{"title": "논의 내용", "type": "free", "description": "※ 안건별로 적는다", "aiFill": true},
            {"title": "할 일", "type": "table", "columns": 3, "aiFill": true}],
 "header": "나인아웃팅 회의록", "footer": "- 2 -",
 "warnings": [{"code": "CHECKLIST_NO_BOX", "title": "확인 사항"}]}
```

- `fields`의 항목 모양은 명세 5.8과 같다. `columns`는 표일 때만, `description`은 설명이 있을 때만 들어간다.
- `aiFill`은 모두 `true`로 둔다 (정할 것 3번).
- 실패는 오류 코드 하나: `unsupported_format`, `encrypted`, `too_large`, `no_text`, `NO_FIELDS`, `CHECK_FAILED`, `LLM_TIMEOUT`, `LLM_FAILED`. 양식 글은 오류 글과 로그에 남기지 않는다.

## 4. 정할 것 (백엔드, 기획)

| # | 정할 것 | AI 쪽 제안 |
|---|---|---|
| 1 | 파일 전달 | RAG 업로드 문서처럼 서명 주소(`fileUrl`)를 받아 서버가 내려받는다 (허용 저장소 설정 필요). 직접 올리는 방식은 AI 서버가 파일을 받는 주소를 새로 만들어야 한다 |
| 2 | 동기·비동기 | 호출 1번이면 끝나고 글이 짧아 한 번에 답하는 동기가 간단하다. 시간 제한과 대기열 사용 여부는 실제 시간을 재 본 뒤 정한다 (아직 안 잼) |
| 3 | `aiFill` | 가져온 항목을 AI가 채울지(`true`) 사용자가 채울지. 양식에는 보통 AI가 채우는 항목이 대부분이라 `true`로 두고 사용자가 화면에서 바꾸는 것을 제안한다 |
| 4 | 읽지 못했을 때 화면 | 실패 코드별 문구(스캔 PDF라 읽을 수 없음, 항목을 못 찾음 등). 일부만 읽은 경우는 경고(`warnings`)로 알린다 |
| 5 | 이름이 겹치는 양식 | 항목 제목이 겹치면 AI가 다시 읽게 한다. 같은 이름이 꼭 필요한 양식은 지원하지 않는다 |
| 6 | PDF 외 형식 | docx 등을 지원할지 |
| 7 | 파일 상한 | 지금 10쪽, 글 2만 자는 AI 쪽 제안값 (실제 양식 샘플로 확인 전) |

## 5. 아직 재 보지 않은 것

- 실제 양식 PDF로 항목을 얼마나 잘 읽는지 (항목 재현율, 잘못 읽은 항목). **실제 양식 샘플이 없어서 평가하지 못했다.**
- 표는 글 추출 결과가 칸마다 쪼개지지 않고 한 줄("항목 금액 비고")로 나온다 (합성 PDF로 확인). 열 개수는 머리 행을 보고 AI가 센다. 선이 없는 표나 병합 칸에서 틀릴 수 있다.
- 호출 시간과 비용. 모델은 1번 부르고, 검사에 걸리면 최대 2번 더 부른다.
- 쪽마다 반복되는 머리글을 첫 쪽 것만 `header`로 쓴다. 쪽마다 다른 머리글은 다루지 않는다.
