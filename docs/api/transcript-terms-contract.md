# AI 서버 전사 속 용어 형식 v0.3 초안

> 회의 중 전사에 낯선 용어가 나오면, 화면이 그 용어에 색을 칠하고 마우스를 올리면 한 줄 뜻을 보여 주는 기능의 형식이다(화면 기획서 Live_24, 요구사항 REQ-191).
> AI 서버는 이 회의에서 찾은 용어 목록을 **안건 보드와 따로** 백엔드에 보낸다. **기본은 꺼져 있다**(`TRANSCRIPT_TERMS=1`일 때만 동작). 켜지 않으면 아무것도 보내지 않는다.
> 백엔드·프론트 확인 전이라 모든 값이 바뀔 수 있다. 확정되면 이 문서를 최신 전체본 하나로 교체한다.

- 근거: 요구사항 명세서 REQ-191(용어 감지. 비고: "AI 용어 감지 필요(ai-service 명세 협의). 지금 화면은 확인용 내장 용어 7개로만 찾음"), 화면 기획서 Live_24(전사 속 용어 호버).
- 모듈: `summary/transcript_terms.py` (`TranscriptTerms`, `Glossary`, `TermsCfg`). 서버 연결은 `server/service.py`(`terms_from_env`, `_publish_terms`), 보내기는 `server/publisher.py`.
- 시험: `summary` 폴더에서 `python transcript_terms.py --selftest`, 저장소 최상단에서 `python -m server.selftest`.
- 예시: `examples/api/transcript-terms-put.json`.

## v0.2에서 바뀐 것

| 바뀐 것 | 이유 |
|---|---|
| 용어 목록을 안건 보드의 `terms` 칸에서 빼고 **새 주소 `PUT .../transcript-terms`로 따로 보낸다** | 안건 보드는 안건 목록이 있어야 나간다. 안건 없이 만든 회의에서는 용어를 찾아 놓고도 보내지 못했다 |
| 회의 중 카드 칸 `hints`(최근 카드 3장)를 뺐다 | 화면은 카드 없이 전사 속 용어 표시(Live_24)만 쓴다 |
| 카드 닫기·끄기·켜기 주소 `POST .../hint-actions`를 뺐다 | 카드가 없어졌다. 표시를 끄는 것은 화면에서 숨기면 된다. v0.2에서는 끄면 용어 목록까지 비어 색칠이 사라졌다 |
| 용어 `id`를 `h-1`에서 `t-1` 모양으로 바꿨다 | 카드(hint)가 아니라 용어(term)라서 |
| 회의가 끝나면 마지막 줄까지 용어집에서 찾고 `final: true`로 한 번 보낸다 | v0.2에서는 끝날 때 들어온 줄을 보지 않았다 |
| 이름을 `agenda_hints`·`AGENDA_HINTS*`에서 `transcript_terms`·`TRANSCRIPT_TERMS*`로 바꿨다 (모듈, 환경변수, `ai.task`, 상태 조회 키) | 안건·카드와 상관없는 기능이 됐다. 배포에서 켠 적이 없어 지금 바꾼다 |

## 1. 목적과 범위

| 구분 | 내용 |
|---|---|
| 목적 | 회의 밖 사람이 모를 수 있는 용어를 회의를 멈추지 않고 알려 준다 |
| 다루는 것 | 용어 목록 보내기, 화면이 용어를 찾아 칠하는 규칙, 팀 용어집 형식 |
| 이 문서 밖 | 회의 중 카드, 지난 회의 카드, 뜻을 더 묻기(회의 중 챗봇이 이미 일반 개념을 답한다), 화면 표현 |

## 2. 용어를 찾는 길

| 길 | 조건 | 모델 | `origin` | 뜻의 출처 |
|---|---|---|---|---|
| 용어집 | 용어집의 `term` 또는 `aliases`가 새 줄에 나옴 | 안 씀 | `GLOSSARY` | 용어집 문장 그대로 |
| AI 설명 | 용어집에 없는 낯선 말 | 씀 (`ai.task=transcript_terms`, 새 값) | `AI_EXPLAIN` | 모델이 쓴 한 줄, 코드가 확인 |

- 줄 묶음이 올 때마다 아직 보지 않은 줄만 본다. 안건 목록이 있든 없든 같다.
- 모델 길은 새 줄이 4개 모이거나(`min_new_lines`), 새 줄이 있는데 음성 시간으로 60초가 지나면(`refresh_sec`) 한 번 부른다. 한 번에 최대 30줄, 응답에서 최대 3개 용어를 받는다.
- 회의가 끝나면(`end`) 마지막 줄까지 용어집 길로만 찾고 모델은 부르지 않는다.

## 3. 보내는 것

`PUT {BACKEND_BASE_URL}/internal/meetings/{meetingId}/transcript-terms` (경로는 `TRANSCRIPT_TERMS_PATH`로 바꿀 수 있다)

```json
{
  "meetingId": 1234,
  "version": 1792455712004,
  "final": false,
  "terms": [
    {"id": "t-1", "term": "리텐션", "name": "리텐션 (Retention)", "aliases": ["retention"],
     "text": "한 번 쓴 사용자가 다시 돌아와 계속 쓰는 비율이에요.", "origin": "GLOSSARY", "firstSeq": 214},
    {"id": "t-2", "term": "코호트", "aliases": [],
     "text": "비슷한 조건의 사용자 묶음이에요.", "origin": "AI_EXPLAIN", "firstSeq": 231}
  ]
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `meetingId` | 백엔드가 보낸 값 그대로 | 회의 번호 |
| `version` | int | 커지기만 한다(밀리초 시각 이상). 더 작은 `version`이 늦게 오면 버린다 |
| `final` | bool | 회의가 끝난 뒤 마지막 목록이면 `true` |
| `terms` | 배열 | **이 회의에서 지금까지 찾은 용어 전체.** 받은 쪽은 덮어쓰면 된다 |

`terms`의 각 항목

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | string | 회의 안에서 유일. `t-1`, `t-2`... 찾은 순서대로 |
| `term` | string | 전사에서 칠할 표기 (모델 길은 앞뒤 공백만 뺀 것) |
| `name` | string, 선택 | 뜻 카드 제목 (예: "리텐션 (Retention)"). **용어집 길에만 있다.** 없으면 화면은 `term`을 쓴다 |
| `aliases` | string[] | 같은 뜻의 다른 표기. 화면이 `term`과 함께 칠한다. 용어집 길만 값이 있고 모델 길은 빈 배열 |
| `text` | string | 한 줄 뜻. 60자 이하 |
| `origin` | string | `GLOSSARY` / `AI_EXPLAIN`. 화면이 `AI_EXPLAIN`에 "AI 설명" 표시를 붙이는 것을 제안한다 |
| `firstSeq` | int | 그 용어를 처음 찾은 전사 줄 번호 |

보내는 규칙

- 목록이 바뀌었을 때만 보낸다. 같은 회의는 1초에 한 번보다 자주 보내지 않는다. 보내는 사이에 더 새 목록이 생기면 옛것은 버리고 새것을 보낸다.
- 찾은 용어가 없으면 회의 중에는 보내지 않는다. 회의가 끝나면 목록이 비어 있어도, 바뀌지 않았어도 `final: true`로 한 번 보낸다.
- 같은 용어(별칭 포함)는 회의 한 번에 한 번만 들어간다.
- 오래된 것부터 최대 200개까지 남긴다. 넘으면 가장 오래된 용어가 빠지고, 빠진 용어는 다시 넣지 않는다.
- 실패하면 다른 결과와 같이 1·2·4초 간격으로 3번 다시 보낸다(408·429·5xx·연결 오류만).
- 안건 보드(`agenda-board`)에는 용어 칸이 없다.

백엔드가 할 일: 이 주소를 받아 회의 방에 전달한다. 화면이 회의 도중에 들어오면 마지막 목록을 줄 수 있게 회의별로 마지막 것을 갖고 있는다.

## 4. 화면이 용어를 찾아 칠하는 규칙

AI 서버는 용어의 글자만 준다. 화면이 전사 각 줄에서 `term`과 `aliases`를 찾아 칠한다. 서버가 용어를 찾을 때와 같은 규칙을 쓴다.

| 규칙 | 예 |
|---|---|
| 영문은 대소문자를 무시한다 | `retention`, `Retention` 모두 칠함 |
| 영문·숫자로 된 표기는 앞뒤에 영문·숫자가 붙으면 다른 말로 본다 | `KPIs`, `RAPID`의 `KPI`·`API`는 칠하지 않음 |
| 한글은 조사가 붙어도 찾는다 | `리텐션이`, `리텐션을`의 `리텐션` |
| 겹치면 긴 표기를 먼저 칠한다 | 목록에 `리텐션율`과 `리텐션`이 있으면 `리텐션율` 전체를 `리텐션율`로 칠함 |
| 받아쓰기 불확실 표시(⟨ ⟩) 안의 글자는 칠하지 않는다 | 화면이 그 표시를 받는 경우에만 지킬 수 있다 (**확인 필요**) |

- 새 용어를 찾는 것은 새 줄이 들어올 때뿐이다. 용어를 찾기 전에 나온 줄도 목록이 오면 다시 칠한다(목록으로 전사 전체를 다시 칠한다).
- 줄마다 칠할 위치(글자 범위)를 서버가 주는 방법은 쓰지 않았다. 줄이 고쳐지면 다시 계산해야 하고, 화면에 보이는 글과 서버의 글이 같은지 확인하지 못했다.

## 5. 코드가 확인하는 것 (모델 길)

| 확인 | 어기면 |
|---|---|
| 용어가 근거 줄 안에 실제로 있다 (영문은 대소문자 무시, 앞뒤가 영문·숫자이면 다른 말) | 버림 (오류로 셈) |
| 그 글자가 STT 불확실 표시 안에 있지 않다 | 버림 |
| 용어 2~20자 한 줄, 뜻 한 줄 60자 이하, 뜻에 「」 인용 없음 | 버림 |
| 근거 번호가 입력 범위 안이다 | 버림 |
| `confident`가 true다 | 조용히 건너뜀 (오류로 안 셈) |
| 이미 찾은 용어, 용어집에 있는 용어, 안건 제목에 든 말(안건이 있을 때만) | 조용히 건너뜀 |

- 낮은 확신도 줄과 맞장구·간투사 줄은 입력에서 뺀다. 한 번 본 줄은 나중에 고쳐져도 다시 보지 않는다.
- 응답이 JSON이 아니거나 모양이 틀리면 오류를 알려 1번 더 부르고, 또 틀리면 실패로 센다.
- 연속 3번 실패하거나 회의당 호출 상한(60)에 닿으면 **모델 호출만** 멈춘다. 용어집 길은 계속된다.
- 모델 실패는 다른 결과(요약, 안건 분류, 안건 보드) 전송을 막지 않는다.

## 6. 팀 용어집 (JSON 파일)

```json
{"terms": [{"term": "리텐션", "name": "리텐션 (Retention)", "aliases": ["retention"], "explain": "한 번 쓴 사용자가 다시 돌아와 계속 쓰는 비율이에요."}]}
```

- `term` 2~20자, `explain` 한 줄 60자 이하, `aliases`는 선택, `name`은 선택이고 한 줄 2~40자. 이름(term, aliases)은 서로 겹치면 안 된다. 어긋나면 서버가 시작할 때 설정 오류로 멈춘다.
- `TRANSCRIPT_TERMS_GLOSSARY_PATH`가 가리키는 파일이 없으면 시작할 때 설정 오류다(경로 오타를 빈 용어집으로 넘기지 않는다). 경로를 비우면 빈 용어집이고 모델 길만 동작한다.
- 내용은 아직 없다. 화면 확인용 내장 용어 7개(리텐션, 온보딩, KPI, MVP, 이탈률, 우선순위, QA)가 프론트 `termGlossary.ts`에 있으니 첫 용어집의 후보다.

## 7. 설정

환경변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `TRANSCRIPT_TERMS` | 0 | `1`이면 켠다. `0`·`1`이 아니면 시작할 때 설정 오류 |
| `TRANSCRIPT_TERMS_GLOSSARY_PATH` | 없음 | 팀 용어집 JSON 경로 (6장) |
| `TRANSCRIPT_TERMS_REFRESH_SEC` | 60 | 새 줄이 있는데 이 시간(음성 시간)이 지나면 용어 후보를 찾음 |
| `MAX_TRANSCRIPT_TERMS_CALLS_PER_MEETING` | 60 | 회의당 모델 호출 상한 |
| `TRANSCRIPT_TERMS_PATH` | `/internal/meetings/{meeting_id}/transcript-terms` | 보낼 경로 (`BACKEND_BASE_URL`과 같은 주소로) |

모듈 설정 (환경변수로 바꾸지 않는 값, 제안)

| 이름 | 기본값 | 설명 |
|---|---|---|
| `min_new_lines` | 4 | 새 줄이 이만큼 모이면 용어 후보를 찾음 |
| `max_lines` | 30 | 모델 한 번에 주는 줄 수 |
| `max_per_call` | 3 | 한 번의 응답에서 받는 용어 수 |
| `max_terms` | 200 | 목록에 담는 용어 수 상한 |

모델은 요약과 같은 `LLM_PROVIDER`, `LLM_MODEL`을 쓴다.

## 8. 토큰 지표와 로그

- `ai.task` 새 값 `transcript_terms`. 켜기 전에 cn 팀 집계가 알아보는지 확인해야 한다.
- 로그와 상태 조회(`GET /internal/meetings/{id}/status`의 `transcriptTerms`. 꺼져 있으면 `null`)에는 전사 내용, 안건 제목, 용어, 뜻을 남기지 않는다. 개수와 예외 이름만 남긴다. 시험으로 확인했다.

## 9. 복구

AI 서버가 재시작하면 찾은 용어 목록이 사라진다. 줄 묶음을 처음부터 다시 받으면 용어집 길의 용어는 다시 찾는다. 모델 길의 용어는 다시 찾을 수도, 못 찾을 수도 있고 `id`가 달라질 수 있다. 해결 방안은 정하지 않았다.

## 10. 이번 범위에서 하지 않는 것

- 모델을 부르는 평가: 용어 후보를 얼마나 잘 고르는지, 뜻이 맞는지는 **아직 재 보지 않았다.** 프롬프트는 실제 모델로 돌려 본 적이 없다. **그래서 기본은 꺼짐이다.** (SCRUM-295)
- 용어집 내용 만들기 (SCRUM-296)
- 줄마다 칠할 위치를 서버가 주는 것 (4장)
- 색칠이 늦게 되는 문제: 줄 묶음이 10초마다 오므로 용어집에 있는 말도 최대 약 10초 뒤에 칠해진다(명세값 기준 추정). 써 보고 문제가 되면 따로 다룬다.

## 11. 협의 상태

| 상대 | 확인할 것 | 상태 |
|---|---|---|
| 기획팀 | 카드 없이 전사 속 표시만 쓰는 범위, 표시를 끄는 설정이 필요한지, `AI_EXPLAIN`에 "AI 설명" 표시를 붙일지 | 미확인 |
| 백엔드 | `PUT .../transcript-terms`를 받아 회의 방에 전달하기, 늦게 들어온 화면에 마지막 목록 주기 | 미확인 |
| 프론트 | 내장 7개 대신 받은 목록으로 전사 전체를 칠하기, 4장의 찾는 규칙, 받아쓰기 불확실 표시를 받는지, `name`이 없을 때 `term` 쓰기 | 미확인 |
| 인프라 | `ai.task=transcript_terms` 집계, 켤 때 설정과 용어집 파일 넣기 | 미확인 |
| 팀 | 용어집을 누가 어떻게 관리할지, 첫 용어집 내용 | 미정 |
| AI(우리) | 실제 회의 전사로 용어 후보 평가 (정밀도, 호출 수, 비용), 켜기 결정 | 미착수 |
