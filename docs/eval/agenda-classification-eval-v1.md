# 안건 분류 평가 결과 v1 (AI-02)

> 회의 1건, 모델 1종, 1회 실행. 베타 전 참고용이며 표본이 작아 통과·미달을 단정하지 않는다.
> 이 문서에는 전사 내용을 넣지 않는다 (줄 번호와 수치만).

## 1. 한 줄 결과

기본 설정(직전 대화 12줄 사용)에서 합격 기준 4개 중 3개를 넘었고, 해당 없음 줄 정확도가 84.4%로 기준(85%)에 1줄 모자랐다.
기본값은 그대로 두고, 베타에서 실제 회의로 다시 잰다.

## 2. 평가 방법

| 항목 | 내용 |
|---|---|
| 데이터 | 29분 25초 회의 1건. 전사 256줄 중 분류 대상 182줄 (맞장구·간투사 3줄, 낮은 확신도 71줄은 제외) |
| 안건 | 4개를 평가용으로 만들었다 (담당 분야 정하기 / 지라 협업 도구 사용 / 클라우드 사용 비용 관리 / 회의 마무리와 팀장 보고) |
| 정답 | 줄마다 안건 또는 해당 없음. 초안을 시간대별로 붙인 뒤 담당자가 그대로 확정했다. 결과를 보고 고치지 않았다 |
| 줄 구성 | 안건 1 = 19줄, 안건 2 = 28줄, 안건 3 = 10줄, 안건 4 = 3줄, 해당 없음 = 122줄 |
| 애매한 줄 | 초안 작성자가 확신이 없다고 표시한 줄 21줄 (경계에 걸친 발언, 앞말을 받는 짧은 말, 곁가지 주제) |
| 재생 | 실제 서비스처럼 10초 묶음으로 보내고, 30초(음성 시간)마다 모델 호출. 한 번에 최대 30줄 |
| 모델 | gemini-3.8-flash (요약 평가와 같은 모델) |
| 변형 | `with_context`(직전 대화 12줄 사용, 기본값) / `without_context`(줄만 보여 줌) |
| 도구 | `summary/eval_agenda.py` |

## 3. 합격 기준과 결과 (with_context)

| 기준 | 목표 | 결과 | 판정 |
|---|---|---|---|
| 전체 정확도 | 80% 이상 (PRD 목표, 베타에서 확정) | 87.4% (159/182) | 통과 |
| 안건 줄 정확도 | 70% 이상 | 93.3% (56/60) | 통과 |
| 해당 없음 줄 정확도 | 85% 이상 | 84.4% (103/122) | 미달 (1줄 차이) |
| 미응답 | 0줄 | 0줄 | 통과 |

호출 59회, 오류 0, 추정 비용 약 200원 (환율 1,400원 가정).

## 4. 직전 대화의 효과

| | with_context | without_context |
|---|---|---|
| 전체 | 87.4% (159/182) | 85.7% (156/182) |
| 안건 줄 | 93.3% (56/60) | 85.0% (51/60) |
| 해당 없음 줄 | 84.4% (103/122) | 86.1% (105/122) |
| 확신 있는 줄 (161) | 94.4% | 91.9% |
| 애매한 줄 (21) | 33.3% | 38.1% |
| 호출 / 입력 토큰(추정) | 59회 / 약 17.4만 | 59회 / 약 10.2만 |
| 추정 비용 | 약 200원 | 약 124원 |
| 걸린 시간 | 299초 | 380초 |

- 직전 대화를 쓰면 "앞말을 받는 짧은 말"(215~220번)을 앞 줄과 같은 안건으로 잘 이었다. 안건 1의 정답 맞힌 줄이 10에서 15로 늘었다.
- 대신 해당 없음 줄을 안건으로 끌어들인 경우가 2줄 늘었다.
- 전체로는 직전 대화를 쓴 쪽이 낫고, 추가 비용은 회의당 약 76원이라 기본값 12줄을 유지한다.

## 5. 틀린 줄 분석 (with_context, 23줄)

혼동표 (정답 -> 예측, 줄 수)

| 정답 -> 예측 | 줄 수 |
|---|---|
| 안건 1 -> 안건 1 | 15 |
| 안건 1 -> 안건 2 / 안건 4 / 해당 없음 | 1 / 1 / 2 |
| 안건 2 -> 안건 2 | 28 |
| 안건 3 -> 안건 3 | 10 |
| 안건 4 -> 안건 4 | 3 |
| 해당 없음 -> 안건 1 | 18 |
| 해당 없음 -> 안건 2 | 1 |
| 해당 없음 -> 해당 없음 | 103 |

틀린 줄 번호: 1, 2, 17, 59, 62, 63, 64, 66, 72, 73, 74, 75, 183, 186, 187, 202, 203, 204, 205, 206, 210, 211, 212

- **해당 없음을 안건 1로 분류한 18줄**이 대부분이다. 62~75번(진로 잡담, 8줄)과, 186·187번 및 202~212번(과거 프로젝트의 테스트 경험 얘기, 합쳐 10줄)이다. 안건 1의 제목·결정할 사항에 "담당", "분야"처럼 넓은 말이 있어 비슷한 단어가 나오는 잡담을 끌어들이는 경향이 보인다.
- 틀린 23줄 중 14줄이 애매한 줄이고, 9줄(1, 2, 62~64, 66, 73~75번)은 애매하다고 표시하지 않은 줄이다. 62~75번은 "맡고 싶은 분야" 얘기라 안건 1로 볼 여지도 있어 정답 자체가 논쟁거리다.
- 1·2번은 회의 첫 발언이라 앞에 맥락이 없다.

## 6. 해석할 때 주의할 점

- 회의 1건·182줄이라 오차가 ±6%p 정도다. 해당 없음 미달(1줄 차이)은 우연일 수 있다.
- 틀린 줄을 보고 프롬프트를 고친 뒤 같은 회의로 다시 재면 점수가 부풀려진다. 개선 효과를 말하려면 새 회의와 새 라벨이 필요하다.
- 안건 4는 3줄뿐이라 이 안건의 정확도는 신뢰할 수 없다.
- 라벨은 한 사람이 초안을 확정했다. 두 사람이 따로 붙여 일치도를 보지는 않았다.

## 8. 다시 돌리는 방법

```bash
cd summary
set -a; . ../.env; set +a        # GEMINI_API_KEY (파일은 커밋하지 않는다)
# 호출 수와 비용 추정만 (모델을 부르지 않음)
python3 eval_agenda.py --transcript T.jsonl --agendas A.json --labels L.tsv --provider gemini --model gemini-3.8-flash --dry-run
# 유료 실행 (결과 파일이 이미 있으면 거부)
python3 eval_agenda.py --transcript T.jsonl --agendas A.json --labels L.tsv --provider gemini --model gemini-3.8-flash --paid-ok --out result.json
```

라벨 파일(TSV) 열: `seq, time, draft, unsure, confirmed, text`. 정답은 `confirmed` 열이다 (안건 id, 해당 없음은 `-`).
전사 파일과 라벨 파일은 개인 대화가 들어 있어 커밋하지 않는다 (`data/`는 gitignore).
