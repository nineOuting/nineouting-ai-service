# rag/prompts

LLM 에 보내는 지시문(시스템 프롬프트)을 모아 둔다. 파일 하나에 프롬프트 하나다.

| 파일 | 쓰는 곳 | 코드가 꼭 필요로 하는 글 |
|---|---|---|
| `answer_system.md` | 답변 API (`rag/answer.py`) | `NO_ANSWER` (근거로 답할 수 없을 때 LLM 이 내는 표시. 코드가 이 글로 no_result 를 판정한다) |

## 형식

```markdown
---
version: answer-v1
---
지시문 본문
```

- 맨 위 `---` 사이에 `version` 을 적는다. 서버 로그에 질문마다 `prompt=answer-v1` 처럼 남아, 어느 지시문으로 만든 답인지 알 수 있다
- 본문은 앞뒤 빈 줄을 빼고 그대로 LLM 에 보낸다

## 고칠 때

1. 본문을 고치면 `version` 도 올린다 (`answer-v1` → `answer-v2`). 바꾼 이유는 커밋 메시지에 적는다
2. 위 표의 "꼭 필요로 하는 글"을 지우지 않는다. 빠지면 서버는 뜨지만 그 기능만 503 이 된다
3. 서버를 다시 띄워야 반영된다 (시작할 때 한 번 읽는다)
4. `.venv/bin/python -m rag.try_answer` 로 같은 질문을 해 보고, 근거 번호와 NO_ANSWER 규칙을 지키는지 본다

자료·질문 칸(`<자료>`, `<질문>`)은 코드(`answer.build_prompt`)가 만든다. 조각 글 안의 꺾쇠를 바꿔 칸 밖으로 새지 않게 하는 처리가 함께 있어서 파일로 빼지 않았다.
